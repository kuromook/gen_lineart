原稿の国勢調査

原稿 9,653ファイルについて、毎回調べ直さなくて済む集計。公開するのは年・形式・種別ごとの件数と分布だけで、作品名・層名・頁のパスは入っていない。

重かったのは数を取ることではなく、数に付く但し書きを毎回引き直すことだった。だからこれは「数の表」ではなく、数と、その数が答えない問いの表である。

1 / 母集団この数は、何の数か

先にここを読む。ファイル数と異なり数は別の量で、層の数はすべて .clip のものである。「測った者」の欄が空の行は無い。

2 / 答えない問い各列が答えないこと

この集計の本体。行のほとんどは、抽出側と基盤が 2026-10-26 に自己訂正した内容から来ている。T<n> は台帳の罠の番号。

3 / 空欄の読み方空欄は 0 ではない

数の表には3種類の空欄が出る。どれも 0 ではなく、理由が別である。

集計していない直る予定のある列。いま入れると誤りが集計に固定される
測っていないその母集団の材料がその量を運んでいない
材料に無いその形式のファイルが手元の材料に1件も入っていない

4 / 頁年ごとの頁数と作品数

年はフォルダーの名前で、暦年ではない。2022b が暦年 2022 の続きかは作者に未確認なので畳んでいない。

5 / 層年 × 種別 × layer_type

layer_type はビット列。確かなのは 1(本体がラスタ)・2(層のマスクがある)・4096(色調補正)の3ビットだけで、16/32/256/512/1024 の位は意味が不明。等値比較で絞ると何かが黙って落ちる。

6 / 全数構造 DB の全数 437,561層

この段だけは抽出側が測った。ここでは DB を持っていないので測れない —— 合うのはこちらの転記と向こうの足し算だけで、DB が壊れていても合う。.clip と .lip で値の種類と振る舞いは同じ(抽出側の明記)。

値は全11種。上の位の組は固定されている

layer_type のビットごとの意味

確かなのは 1・2・4096 の3ビットだけ。16 / 32 / 256 / 512 / 1024 は「不明」のまま持つ —— 抽出側は「特殊な層と呼びたくなるが確かめていない」と書いた。

2の位とマスク —— コマ枠フォルダーは別の行

混ぜると 8,734 が例外に見える。ただしマスクの向きは層の種類からは決まらない —— 普通のフォルダーにも init 0 のマスクが在る(2026-10-26 の訂正)。

visibility の食い違い —— どちらの数も母集団つきで持つ

優先65頁の 245 と全数の 119 は別の量。抽出側は一度「置き換えて」と書き、その後取り消した。

7 / 本体本体の InitColor(ここで測った)

1層1行の納品なので、要約を引用せず行から数え直した。raster_cover = 0.0 の 132層が 96(init 255)+ 36(init 0) に分かれることは、ここで検算した数である。段 A では set 列の作品名を種類に畳んでいる(段 C では畳まない)。

8 / 納品届いたもの —— 枚数は層の数ではない

data/incoming_manuscript/ の13の納品を歩いて数えた(段 A には納品フォルダーの名前を出さない)。何が1枚かが納品ごとに違う —— mask だけの納品、本体だけの納品、両方の納品が在る。優先65頁のトーンは mask 619 に対し本体 683 で等しくない。カラー原稿には頁のプレビューが混ざる(層ではない)。

行 / 枚

画布の宣言値 —— 単位がこの材料では決まらない

33頁の材料には canvas_unit 列が無い。497×277 や 210×297(mm と読める)と 3000×3000 や 2033×3433(px と読める)が同じ列に並ぶ。どちらかをここで決めない —— v_canvas_px_w/h を待つ。

同じ名前が2つの納品に在る 1,636枚 —— うち 256枚は中身が違う

標本20枚の sha256 は「20/20 一致」と出た。違うと分かっている組(壊れた初版の差し替え)を含んでいなかった。全組を名指しで比べて出た数である。どちらが現行かはここで決めない —— 版の同定は名前や統計量では決まらない。

9 / 出所材料と、値が動く予定の列

受領 CSV の sha256 と、抽出側が読み手を直したら値が変わる列。動いたらこの集計の該当行は古くなる。
