そして「可視」の列は、描かれていることを言っていない(2026-10-27、基盤が自分の点検で踏んで回送した罠) —— share_visible_bit と share_opacity_full はその層自身の値で、祖先のフォルダーが非表示なら、層が可視でもその層は描かれない(クリスタの描画の事実)。だから隣に share_ancestor_hidden を出した:帰無値 0.074 に対して、既定の時刻名 0.497(可視の半分が描かれない)/ blender 0.063 / ホワイト 0.008、黒消しのフォルダーの中は 1.000。1つの割合では代表できない。

行 / 枚

重複は3つの別の量 —— 引き算で作った数は、引き算の意味を名前に持たない

7,667 − 6,194 = 1,473 を「複製の数」と書くと、2,458 を 1,473 と報告する。A − B は量ではなく手続きである。この集計はこの引き算をしない —— 量ごとに行を持つ。全 9,653 行の sha256 が来たので、ここで測った数である(ハッシュ自体は抽出側が計算した列)。
.lip の双子は 67.8%、.clip は 32.1%。ただしこれは形式の性質ではない —— .lip の双子 1,346 のうち 1,294(96%)は、作品フォルダーが丸ごと2〜3の年フォルダーに置かれていることによる。作者の言明(この時期は制作の運用が安定せず、作業途中のコピーが残った)と一致する。欠陥ではなく仕事の仕方である。そして 63ファイルの塊は、21頁の白紙の型紙が3か所に在るもの(暗い画素 0%)。述語は数と同じ行に在る —— 索引に置くと数だけが流通する。

塊の大きさ

被覆の値は、値か下限か —— 線の層には当たらないと計数できた

2026-10-27 に依頼3の 56,576層で計数できた(それまで「機序は確定・件数は未計数」)。決定的な結果:本体がラスタの層(= 線の層)は body_init = 0 の分類にしか居ない —— そこでは読み手の 0 埋めが InitColor と一致するので偏りが原理的に生じない。線の層の drawn_ratio は、下限でも偽の 0 でもない。
危険は塗り・トーン・用紙・色調補正に限られる:分類5(下限)は 512層(用紙 109 + 色調補正 403。値が在るのは 218層だけで、294層は空欄 = 下限にすらならない)、分類1(255 + 保存0)が 11,499層(ほとんどが layer_type == 2 = マスクのみでラスタ本体が無い層。これは v_layer_kind = mask_fill と同じ集合ではない)で drawn_ratio は全部 0 だが InitColor どおりなら全面 —— 危険は消えたのではなく階級が移った。

drawn_ratio の閾 26 が落としている薄い画素

alpha_ge1_ratio(アルファ≥1)との差が、落ちている量。本体がラスタの層で落ちているなら、それは薄い線である。

本体の InitColor の分類(2,095層の納品)

描画用の読み手は保存されていないブロックを 0 で埋めるので、body_init 255 で一部だけ保存された層では値が小さく出る。0 は特別ではなく、下限が 0 まで下がった場合でしかない。本体が届いた 2,095層を数えると 255 + 一部保存 は 0層 —— 列全体を下限扱いする必要はない。ただし依頼3の 56,576層には blocks/stored が無いので、そちらの該当数は未計数(機序は確定、件数が無い)。

グラデ v1/v2 を層を鍵に—— 名前を鍵にした 152 の正体

供給元の対応表(258層)から数え直した。名前を鍵にすると 152枚が「違う」と出るが、層を鍵にすると 131 は画素が同じで名前が違うだけで、本当に画素が変わったのは 21層(mask_cover が動いた層数と一致)。103層は v2 で加わった層で、これが採番を後ろにずらした原因である。

画布の宣言値 —— 単位がこの材料では決まらない

33頁の材料には canvas_unit 列が無い。497×277 や 210×297(mm と読める)と 3000×3000 や 2033×3433(px と読める)が同じ列に並ぶ。どちらかをここで決めない —— v_canvas_px_w/h を待つ。

同じ名前が2つの納品に在る 1,636枚 —— うち 256枚は中身が違う

標本20枚の sha256 は「20/20 一致」と出た。違うと分かっている組(壊れた初版の差し替え)を含んでいなかった。全組を名指しで比べて出た数である。どちらが現行かはここで決めない —— 版の同定は名前や統計量では決まらない。

画素を鍵にして取り直す —— 256 のうち多くは名前のずれだった

_grad{N} の N は頁の中の順番で、v2 で層が加わると後ろにずれる。名前を鍵にした差分は、採番のやり直しを「変更」として報告する。画素(sha256)で突き合わせ直すと、グラデの重なり 104画素のうち 101 が別の名前で在った。一方ベタのマスクの差し替え46枚は画素の重なりが 0 —— 本当に全部変わっている。層を鍵にした数は供給元の対応表が要る(未着)。どちらの版が現行かは、この集計では空けてある。
