**ここに置いたものは全世界から読める。**

   **作品名も層名も頁のパスも置かない。**

4. **器具が「固有名を含む列は0」と印字しない走行の出力を commit しない**
5. **各数の隣に「その数が答えない問い」を置く** —— `doc/census_spec.md` §3-3。
   **これが無い集計は、重さを減らさない**(この集計が存在する理由そのもの)

**公開した行を束ねる数は、行を持っている器具が計算する。表の読み手が計算しない**
(2026-10-27、T140)—— **ここの割合の列は小数3〜4桁に丸めてある。**
**公開物の桁数は公開の性質であって、測定の性質ではない**ので、
**公開された数で算術をすると、公開の精度を受け継ぎ、測定の精度を失う。**
実例: `0.025 + 0.061 = 0.086` と書いたが、**数から出すと 0.0853**(誤差 +0.84%)。
**束ねた数が要るときは、束ねる組を器具に宣言させる**(`NON_PICTURE_KINDS` の形)——
**出てきた数が誰の測定にも辿れないことが、誤差の大きさより悪い。**

**読み方の順序は `populations.csv` → `caveats.csv` → 数の表。**
数の表だけを読むと、この集計が止めようとしている誤りがそのまま起きる。

**`index.html` では、各列の見出しに `?` が付く** —— 押すとその列の「答えない問い」に飛ぶ。
**`?` の無い列は、但し書きが登録されていない列である**(無いことが見える形にしてある)。

**空欄は 0 ではない** —— 「その母集団では測っていない」か「集計に入れない列」。
どちらかは `caveats.csv` と `provenance.csv` に書いてある。

**`measured_by` を読むこと。** 全数 437,561層の表は**抽出側が測った数**で、
ここに DB は無い。合うのは**こちらの転記と向こうの足し算**だけで、
**DB が壊れていても合う。**

**遮蔽物は、名前でも種別でもなく順序の性質である。** 名前側は全数に届いたが、
**素性側(画素の分布)は8頁しか届かない** —— **「両面一致」と書ける範囲は8頁である。**
**フキダシは頁の中では手前寄り(中央 0.152 / 帰無値 0.500)で、親の中では後ろ寄り(0.750)** ——
**文字がその上に乗るからで、どちらも正しい。同じ列名に入れない。**
**そして手前に在ることは、重なっていることではない**(何を隠しているかは画素が要る)。

**名前で集めると年によって見つかる物が違う** —— **一様な取りこぼしではなく世代と相関した
取りこぼし**(黒消し 2014〜2016 だけ、**フキダシだけ通年**)。

**マスクの向きを層の種類から決めてはいけない**(2026-10-26 の訂正)——
普通のフォルダーにも `init 0` のマスクが在る。`body_initcolor.csv` の交差表で読む。

**納品の枚数を足さないこと。** **同じ名前の PNG が2つの納品に 1,636枚在り、
うち 256枚はバイトが違う。** ただし **`_grad{N}` の `N` は頁の中の順番**なので、
**名前を鍵にした差分は採番のやり直しを「変更」として報告する** ——
画素を鍵にすると、グラデの重なり104画素のうち**101 は別名で在るだけ**だった。
**どちらが現行かはこの集計では決めない**(供給元の言明として持つ)。

**`9,653 − 7,418` も `7,667 − 6,194` も、この集計はしない。**
**引き算で作った数は、引き算の意味を名前に持たない** —— 「複製の数」と名乗ると
**2,458 を 1,473 と報告する。** 量ごとに行が在る(`duplicate_quantities.csv`)。

**`.lip` の双子は 67.8%、`.clip` は 32.1%。ただしこれは形式の性質ではない** ——
`.lip` の双子 1,346 のうち **1,294(96%)は、作品フォルダーが丸ごと2〜3の年フォルダーに
置かれている**ことによる(作者の言明と一致する。**欠陥ではなく仕事の仕方**)。
**63ファイルの塊は、21頁の白紙の型紙が3か所に在るもの**(暗い画素 0%)。
**述語は数と同じ行に在る** —— 索引に置くと、数だけが流通する。
