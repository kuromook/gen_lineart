## 正規化 —— **登録するのは1つ**

1. **白点を両側で揃える**(§0-4 の裁定)。各画像の紙 = **最頻値 `m`** を取り、
   `v' = clip(round(v * 255 / m), 0, 255)` を当てる。**作者側にも外部側にも同じ式を当てる**
   (作者側は 254 → 255 でほぼ無変化)。**側ごとに違う操作をしない**
   - **対称でない点を1つ明記する**: **作者側は 480タイル単位、外部側は生成画像単位(窓を切る前)で `m` を取る。**
     理由は、作者側は元コマがこの track の手元に無く、タイルしか無いため。**これを走った後に変えない**
2. **閾値は固定 128 / 220。側ごとに変えない**
3. **窓は両側とも 480×480。** 作者側は既存のタイルそのまま(裁定6: 既知セルを引き直さない)
4. **寸法・dpi・ビット深度・ファイル名・圧縮痕を使う軸は名前で除外**
5. **圧縮の経路を揃える**(素案 §正規化-5)。**外部側も作者側と同じ JPEG 経路を通す** ——
   mode `L`、**PIL `quality=95`**、`subsampling=0`。作者側はすでにその形なので**引き直さない**。
   **これを飛ばすと、一番効きそうな faint 3軸が圧縮を読む**
6. **墨の門 = `ink_ratio ≥ 0.011992`**(= 作者側プール 1,489枚の最小値。
   **外部側を一度も見ずに、作者側の母集団の構造だけから決めた**)。**両側に同じく当てる。**
   作者側は定義上1枚も落ちない。**落ちるのは外部側の白紙窓だけ。落とした数を両側で印字する**

**代替の正規化(感度の腕。名前をいま書く。走った後にこの中から選び直さない)**:
(i) 線幅を揃えてから測る / (ii) 両側を `LineartDetector` に通す(= A2/NC4)/
(iii) 白点を揃えない(= A0 の一部)/ (iv) **生成解像度を変える**(下の「構図のスケール」)。

### **残る既知の弱点: 構図のスケールは揃わない**

作者側のタイルは、元コマを**ある倍率で縮小してから**切った 480 窓である

**この走行の結論は、この一点について常に「スケールの差が残っている」と添えて読む。**

## Pass criteria

**`null` = 腕 A3(`ink_ratio` 単独)の、その作品での AUC。**

- **C1 一般の軸**: `AUC ≤ null + 0.05` → その軸は作者の情報を持たない。**最適化しても作者は出てこない**
- **C2 作者固有の候補**: `AUC ≥ null + 0.15` **かつ NC2・NC3・NC4 を通る**
- **C3 どの軸も C2 を通らない** → 計測一式に作者固有の内容が無い。**この線の仕事が間違っていると書く**
- **判定保留の帯**: `null + 0.05 < AUC < null + 0.15`。**判定保留は正直な結論である。
  「棒に届かなかった」と「判定できなかった」は別。両方書く**
- **`line_width_p50` と `width_consistency` は、C1 に落ちても「作者の情報が無い」と読まない**(§0-3)。
  **読みは判定保留に落とす**

### 棒が動いたと見なす形(先に書く)

走った後に、**正規化を選び直す / 白点の取り方を変える / 墨の門 0.011992 を動かす /
タイルの枚数や捨て方を変える / 作品の畳み方を変える / チェックポイントを足すか替える /
プロンプトの語彙を足す / `null + 0.05` か `null + 0.15` を動かす** —— **どれも、向きがどちらでも棒を動かしたことになる。**
