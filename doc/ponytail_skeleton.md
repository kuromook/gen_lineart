## 0. なぜ要るか —— moat の線引きが、主要事例を外へ追い出している

`moat` の description にこうある:

> *Not for ordinary feature or UI work, where no claim rides on the code.*

**2026-10-26 の事故は、この一文が間違っている場所を指した。** 作者の
**20/34 = 0.5882 [0.4070, 0.7535]**、**43/54**、**64問/3.8分** —— どれも UI の出力である。
claim は乗っていた。それでも moat は **`go()` が走らないこと**について何も言えなかった。

**「測定か機能か」という軸で切ったのが原因。** このプロジェクトの UI は **5本とも測定器具**で、
重なりは例外ではなく主要事例である。主要事例を `either/or` で切ると必ずどちらかが漏れる。

---

## 1. 切る軸 —— 「何が希少か」「何が黙って壊れるか」

| | **moat** | **ponytail** |
|---|---|---|
| 希少なもの | **信用**(数が覆る) | **人間の注意**(二度と返らない) |
| 黙って壊れる形 | 棒を後から引く・対照が無い | **押せない・意味が通じない・答が消える** |
| 失敗の代価 | 結論の撤回 | **作者の3分 + 作り直しの1日** |
| 中心の問い | *反対の結果が出たら、言うことが変わるか* | ***人間が来る前に、自分で最後まで通したか*** |
| 合言葉 | 外堀を埋めてから数を出す | **人が来る前に、通しで触る** |

---

## 2. 構造 —— 排他ではなく「積む」。縫い目は ponytail 側に置く

```
ponytail  ── 画面・やりとり・人間の時間        ← UI を書く人が読む
   ↕  縫い目(§4。4条)
moat      ── 量・棒・対照・母集団              ← 数を出す人が読む
```

**縫い目を moat ではなく ponytail に置く。** 違反するのは常に UI を書いている側なので、
**その人が読む場所に無い規則は効かない。**

---

## 3. 規則の候補(10条)——**この repo が実際に代金を払ったものだけ**

| # | 規則 | 出所 |
|---|---|---|
| 1 | **自分で最後まで通す。** 門は「起動したか」ではなく**「1問に答えられたか」**を見る | **T108**(構文検査と HTTP 200 は `go()` を走らせない) |
| 2 | **流用したら接点を差分する。** 器具の接点は**データの鍵の名前** | **T108**(22鍵中3件欠けて解答欄が全滅) |
| 3 | **前の器具が持っていた門を引き継ぐ** | **T110**(m27 が3回落とした層を m47 が作者に出した) |
| 4 | **既定値を主張にしない。** 不明なら「不明」と出す | 倍率が無いと**「(原寸)」**と表示された |
| 5 | **画面にこちらの分類名を出さない** | 「テンプレートの外」→**「質問の意味が分からない 外とは？」** |
| 6 | **選択肢の外に出口を必ず置き、その使用率を印字する** | 「3つか4つか」の答が**5つ**だった |
| 7 | **人間の答を黙って捨てない。** 保存を確認してから次へ | 400 を見ずに進んで**72問**消えた |
| 8 | **位置を固定する**(答の並びが動くと覚えた指が使えない) | 作者の指摘(2026-10-25) |
| 9 | **時間を先に宣言し、後で実測を出す。超過は欠陥** | 「18問・3分」/ 実測 64問 3.8分・34層 5.1分 |
| 10 | **出さなかった問いを理由別に数える** | 設計30問 → 実際18問(moat 規律9 を画面に当てた形) |

**順序の案**: 1 → 2 → 3 が「器具として壊れていないか」、4 → 8 が「人間に嘘をつかないか」、
9 → 10 が「時間と標本の会計」。moat の `The order` と同じく**上から埋める**。

## 4. 縫い目(4条)—— ここだけが両方に触る

1. **盲検** —— 画面に**腕・層別・由来**を出さない
   (2026-10-26: `info` 行の `pid` フルパスから `illustration` が読めた)
2. **既定値の禁止** —— **画面に出る量は測定値である**(§3 の 4 の再掲。縫い目側にも置く)
3. **書き込み先の所有** —— 流用した器具が**前の器具のファイルに書かない**
   (2026-10-26: `X` が L の `labels/fill_anomaly.jsonl` に書いた)
4. **落とした問いの偏りの申告** —— 門で落とした標本は無作為ではない
   (2026-10-26: 落ちた成分は「面が多い側」に偏りうる)

## 7. ponytail の**外**(スコープの防壁)

**入れない**: 見た目の設計・配色・フレームワーク選定・一般的なアクセシビリティ。
**ponytail の主題は「人間とのやりとり」であって、インターフェースの美しさではない。**
これを書いておかないと、一般的な UI スキルに膨らんで、どの規則も効かなくなる
(引き継ぎ文書が900行を超えて機能しなくなった実例をこのプロジェクトは持っている)。
