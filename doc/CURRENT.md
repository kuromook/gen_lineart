## 2. ここに何があったか

このファイルは `2372` 行の `doc/CURRENT.md` で、**2026-10-10 時点**(このブランチの分岐点)で凍結していた。
2026-10-23 時点で生きた版は `5850` 行、**3478 行遅れ**。

**なぜ危険だったか**: 凍結コピーは冒頭で「**This file is the first document to read**」と
名乗っていた。白紙のセッションが素直にそれを読むと、**何か月も前の到達点・既に撤回された数値・
存在しない登録**を現在として受け取る。2026-10-10 以降に台帳が記録した撤回・判定・罠は、
1件もこのコピーに入っていない。

## 3. なぜ警告ではなく削除なのか

順路に「このファイルは古い」と警告を書く手当ては、**警告が先に読まれなければ効かない**。
このファイルを直接開いた者には届かない。**主張しているファイルそのものを消す**のが、
含意ではなく性質を断つ手当てになる。
—— 名前が現在性を約束していても、**約束は含意であって点検ではない**。

基盤の audit(`tools/audit_track_ledger.py` 点検7)は、**ローカルコピーがこの主張を
まだしているか**を見る。だからこのポインタになった木は報告されず、順路に警告だけ書いた木は
報告され続ける。

## 4. `git merge foundation` ではここが衝突する

**解決は foundation 側を採る。** merge 後は生きた台帳そのものになるので、
このポインタは役目を終える。**凍結コピー側を採ると元に戻る。**
