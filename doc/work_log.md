## 【2026-09-21】生成モデル比較(セット一括 vs 2段)の事前登録(Track G 最初の実験・結果未見)

### 問い
条件(ショット型12+WD14タグ上位40)から「単語集合+配置」を出す生成モデルを
**セットモデル(一括)**と**2段(選択→配置)**の2案でスモーク規模に実装し、
配置の bits と目視モンタージュで選定する(initial_notice「最初の一手」1. のとおり)。

### 共通設定
- データ: Track F `results/grammar_corpus_20260920/corpus.npz`(5,345コマ・split 不変。
  train 4,065 / test 1,280)。ビン化・正準順(粗大先行)も Track F 仕様のまま。
- 条件: `labels_k12.npy`(12型→embedding) + `tags_top40.npy`(40多値→線形射影)。
  **両方を常時使用**(Track F cloze では別実行だったが、生成の concept 条件としては一体物)。
- スモーク規模: 学習は train の**先頭1,024コマ**、評価は **test 全1,280コマ**
  (Track F と同一テスト集合で数値を並べるため訓練だけ絞る)。
  epochs 10・batch 32・d256/4層/8頭/dropout 0.1・lr 6e-4・OneCycle・bf16・clip 1.0
  (= Track F cloze と同一学習予算)。
- bits 定義: Track F と同じく「1まとまりあたり平均 CE ÷ ln 2」。pos bits = py+px 合計
  (scale は併記)。評価は teacher forcing(生成品質の目視は別途サンプリングで)。

### 基準(結果を見る前に固定)
ユーザー提示の基準案(そのまま採用、解釈のみここで固定):
「配置の bits が Track F 実測(条件なし 7.398 / 型条件 7.312、unigram 7.348)を上回る」
→ **「上回る」= 性能で上回る = bits で以下**、と解釈する。要求を最良値 7.312 以下に
絞るのは厳格化の方向なので事後緩和には当たらない(ここで記録)。
1. **選択(word)bits ≤ 7.312**(Track F 実測最良値。7.398/7.348 との併記も必須)
2. **配置(pos y+x)bits**: < 7.563(周辺分布)かつ Track F cloze 実測帯 6.315–6.388 と同等以下
3. **目視**: 条件つき生成サンプルのモンタージュを results/ 配下に作り「コマとして読める」
   を確認。数値には画像パスを併記(鉄則)
4. 2案の選定は配置 bits と目視で行う。基準の事後緩和は不可

注意(登録時点で明記): 2段の第1段は「条件+先行単語のみ」で語を生成する
(位置はまだない)。Track F cloze は「他の全まとまり(語+位置)」を見ているので、
cloze より文脈が**厳しく**、word bits の基準(1)は 2段にとって保守的である。
これはアーキテクチャの差そのものなので測定として記録する(不合格でも切り分け情報)。

### 2案の設計(同じ予算・同じ4フィールド出力)
- **セットモデル(一括)**: コマのまとまり列(正準順)を AR 生成。各ステップで
  条件+先行まとまり(語+位置の両方)から次のまとまりの (word, py, px, sc) を
  4 head で同時予測。因果マスク Transformer。
- **2段(選択→配置)**: 第1段で条件+先行「単語」から語列のみを AR 生成
  (位置の入出力なし)。第2段で条件+「全単語」+先行位置から (py, px, sc) を
  AR 生成。語の内容は第1段のサンプルそのもの(配置段で語は変えない)。
- 生成(モンタージュ用): 温度1.0サンプリング。EOS が出るか 170 まで。
  配置はビン中心への配置(Track F render_cloze の nat_place と同式: scale は
  2^(S_LO+(sc+0.5)/12*(S_HI-S_LO))、中心は (py+0.5)/16*H, (px+0.5)/16*W)。

### 道具健全性チェック(訓練前に実行・合格が前提)
- test 集合に対する train 頻度の unigram が ≈7.348、周辺分布が ≈7.563 になること
  (Track F と同じデータ・同じ集計を読んでいることの確認)
- ランダム初期化モデルで word bits ≈ log2(500) ≈ 8.97、pos ≈ 8.0(16×2)、scale ≈ 3.58(12)
  ※登録直後の訂正(結果未見): 当初「scale ≈ 5.2」と書いたが nats/bits 混同の誤記。一様分布は log2(12)=3.58 bits
- 語原型の復号モンタージュ(数語)で「原型が破片でない」を目視確認

### 実行順序

  順序情報を持つため。語彙の性質ではない
- **rank 別分解**: rank0(最 coarse・文脈なし) が入口の難所(word 7.86 / pos 7.64、
  いずれも unigram・周辺を悪化)。rank が進むほど予測しやすい。Track F cloze が
  「ランク無作為に1個抜く」のに対し AR は全ランクを平均する → 平均の差の主因

### 解釈
Track F 結論(「選択には文法がなく・配置には構造がある」)の可視化になった。
配置の統計(どのへんにどのくらいの大きさで何かが置かれるか)は学習できるが、
**何を描くか(語の選択)が場面の意味と結びつかない**限り、原型の束は「蟻の群れ」の
まま。モンタージュはそのことを正直に見せている(これは失敗ではなく測定結果)。
