## 2026-10-23(同日、夜): 作者の回答 —— `black` は**世代による**。ako6 を統計で判定した

### 1. 作者の工程知識(導出不能。規律6。原文の要旨)

> トーンレイヤ方式を始めた頃は、この `black` を**ベタとして扱う予定**だった。
> だが実際に始めると、**デジタル線画の工程でベタを入れてしまう動作が発生しやすく**、
> `black` は**線画と一体となりつつも、ベタのみの `black` が作られるようにもなってきた**。
> **線画をアナログに戻した後には、またベタが線画から分離**したりしている。
> つまり**世代によって「ベタ」と呼ぶべき世代がある**。
> (201x時代の)**ako6, ako7 がどうであるかは、レイヤ名だけでなく統計情報も見て判断が必要**。

**だから `black` が ベタ か否かは作品横断の定数ではない。工程の世代の関数である。**
L が §7 で「作者に聞く問い」として挙げたものへの回答で、**「聞けば決まる」ではなく
「測れ」という回答**だった。以下その測定。

### 2. ako6 の判定: **`black` はベタである**(全107ページ・781層の形の統計)

| 層名 | 層数 | 塗りpx | keep4 中央 | keep4 p10 | r_max 中央 | 作品のベタ面積の占有 |
|---|---:|---:|---:|---:|---:|---:|
| `線画`(無名) | 144 | 180,614,768 | 0.733 | 0.144 | 39.9 | **41.4%** |
| **`black`** | **177** | 117,931,329 | **0.994** | **0.955** | **135.2** | **28.2%** |
| `線画 hair` | 171 | 34,556,584 | 0.414 | 0.107 | 17.9 | 5.6% |
| `線画 skin` | 154 | 27,469,759 | 0.627 | 0.377 | 17.8 | 4.2% |
| **`hair black`** | **16** | 11,015,862 | **0.979** | 0.954 | **149.4** | 2.6% |

**`black` / `hair black` は keep4 0.994 / 0.979、r_max 中央 135 / 149px。**
半径4の開きがほぼ全部を残し、内接半径が130px超 = **線ではなく塊**。
**ako6 において `black` はベタと呼んでよい。** 標本ではなく全数。

### 3. ただし**分離は途中**で、名前は**両方向に**当てにならない

- **ページごとの同居**: 両方を持つ **77** / 融合のみ **25** / **分離のみ 0** / 計102ページ。
  ページごとの「分離ベタが占める割合」中央 **0.496**(p10 0.000 / p90 0.854)
- **無名 `線画` 144層(面積の41.4%)は二峰**: keep4 0.9以上が **59層**、0.2以下が **26層**。
  **同じ名前が、純粋なベタ層と純粋な線層の両方を指している**
- **`線画 hair` 171層は keep4 0.414** = 本当に線と融合している

**作者の「線画と一体となりつつも、ベタのみの black が作られるようにもなってきた」が、
ako6 ではこの形で同時に成立している。** 分離ベタは面積の 30.8%、融合ベタが 54.3%。

### 4. これが §6-2(ラスタがベタを欠く)の機構だった

**線画ラスタは「線と分類した層」で合成される。だから:**
- **分離したベタ(`black`)は落ちる** —— 墨として在るのは **14.2%** だけ
- **融合したベタ(`線画 ...` の中の面)は残る** —— **83.7%** が墨として在る

**ako6 の線画ラスタは、制作ベタの画素の 46.4% を含んでいない**
(在墨 66,226,148 / 制作 123,596,784 = 53.6%、223コマ)。

**そして一般形はこうなる**: **ラスタがベタをどれだけ失うかは、その作品の世代の関数。**
完全に分離した世代ならほぼ全部を失い、完全に融合した世代ならほとんど失わない。
**つまり `ako7` の測定は ako7 の話ではなく、世代の話である。**

### 5. `ako7` は**まだ判定できない** —— 形の統計が無い

**画素が未納品**(納品は ako6 のみ)。手元の `fill_tone_inventory_layers.csv` は

## 2026-10-23(深夜): 面の標準 —— 「層ごと選抜」が第三の道になる

基盤が3経路の地図を整理してくれたが、**提案された経路1の手当てが、経路2の反論にそのまま落ちる。**
そこを分けると道が1本出る。

### 1. 基盤の地図の穴

基盤の提案: 経路1(層まるごとは線が混じる)の手当てとして
**「層の中で形の試験を通る画素だけを採る」**。
基盤の経路2の読み: 循環するのは**「半径4で切った面を半径4のマスクで評価する」場合だけ**。

**この手当ては、まさにその場合である。** 画素を keep4 で切れば、標準の境界が半径4の開きで決まり、
半径4のマスクで評価する。**経路1の手当てが経路2の反論に落ちる**ので、2つは独立していない。

### 2. 分けるべきもの —— **選抜**と**切り出し**は別の操作

- **画素を切る**(pixel-level): 標準の**境界**が半径4で決まる → **循環する**
- **層を選ぶ**(layer-level): 標準の**境界は作者の層のまま**。半径4は
  **どの層を標準に採るか**にしか使われない → **境界は循環しない**

**後者なら、標準の1画素1画素は作者が引いたもので、器具が引いたものではない。**

### 3. 測った: 層ごと選抜(keep4 >= 0.95、画素は切らない)

| | 層数 | 画素 | **まるごと採った時の線の混入** | 作品のベタ面積の被覆 |
|---|---:|---:|---:|---:|
| ako6 keep4>=0.95 | 316 | 357,108,524 | **0.6%** | **86.0%** |
| ako7 keep4>=0.95 | 140 | 151,200,615 | **1.2%** | **76.7%** |
| ako6 `beta`名・非トーン | 59 | 42,961,849 | 1.4% | 10.3% |
| ako7 `beta`名・非トーン | **2** | 2,137,942 | 0.2% | **1.1%** |

**経路1の問題(線の混入 13.7%)は 0.6〜1.2% まで落ちる。**
そして**名前で選ぶより被覆が桁違いに広い** —— 名前選抜は ako6 10.3% / **ako7 1.1%**。

**`beta` 名の標準は ako7 では使えない**(2層・1.1%)。
L1 の時点では「名前で選んだ純粋な標準」を本命と書いたが、**2作品目でそれが崩れた。**
`black` が増えてもトーンフォルダの下に行くので、非トーンの `beta` 名は減る。

### 4. 残る限界(先に書く)

**選抜の偏り。** keep4 < 0.95 で外れるのは、まさに**線と融合した層** ——
マスクが苦手なはずの場所である。だから**この標準で測った一致は、マスクに有利な側に偏る。**
**偏りの大きさは被覆で抑えられる**: 外れるのは作品のベタ面積の **14.0%(ako6) / 23.3%(ako7)**。
**この2つの数を一致の数と同じ行に書くこと**(規律: 数と条件は同じ行に載せる)。

### 5. まだ測っていない

**この標準に対する半径4マスクの一致は未測定。** 本節は**標準の提案とその純度・被覆**までで、
**判定ではない**。回すなら L1 と同じ手順(`pid` 鍵・train 側・原寸・陰性対照2本・

### 4. 一般形

**外部標準が選別を通って来ているなら、その選別が落としたものは「不在」ではなく「不可視」。**
不可視を陰性として数えると、**器具の正しい発火が誤りに化ける。**
今回は**正解の側の感度**を点検せずに、正解を正解として使った。
L1 で「抽出側は色を試験し、L は形を試験する。だから一致は情報になる」と書いたが、
**色の試験に落ちた層は、形の試験にかける機会すら無い**という片側性を見落としていた。

### 5. 必要なもの

**完全な正解。** 納品は色の試験で選別されるので原理的に不完全。
完全なものは1つある —— **作者の完成ページ**(抽出側が `preview_dark` を計算している
`CanvasPreview`)。**完成ページで暗い領域 = 作者が実際に黒くした全て**で、
層の名前にも色の試験にも依存しない。**依頼を出した(`outbox/`)。**

**それが来るまで、マスクの精度に関する数字は出さない。**

### 6. 完成ページも「ベタの正解」ではない(基盤の指摘、2026-10-24)

**依頼した完成ページには、ベタ以外の黒が全部入る** —— 枠線、フキダシの縁、描き文字、
紙面の調度、そして焼き込まれていればトーンの網点。

> **「暗い領域 = 作者が黒くした全て」は正しい。「暗い領域 = ベタ」ではない。**

面として使うには**そこから線と調度を落とす段**が要り、**その落とし方が今度は選別になる。**
**だから完成ページも、使い方次第で同じ罠に入る。**

**違いは選別の位置**: 抽出側の色の試験は**向こう側の入口**にあってこちらからは見えなかった。
完成ページを使えば選別は**こちら側**に来て、**開示でき、点検でき、撤回できる。**
**選別を自分の側に持ってくることが、この依頼の本当の利得**であって、
「選別が無くなる」ではない。

**依頼に入れた「網点が焼き込まれているか」の確認は、ここに効く。**

### 7. そして一致の論証の前提が崩れていた(L1 §4 の文)

L1 はこう書いた(基盤の文をこちらが採用した):

> 抽出側は色を試験し、L は形を試験する。**どちらも他方から作られていない**から、
> 一致は情報になり不一致はどちらを見るべきかを示す。

**後半が成り立っていない。色の試験は入口で、形の試験が何を見られるかを絞っている。**
置き換え(基盤が台帳に入れた形):

> **2つの器具が2人の証人になるのは、どちらも他方の取り込み口より上流に居ないときだけ。**

### 8. 撤回の作法として残すこと

**数値は消さずに残し、撤回を中身として書く**(基盤の判断、採用)。
数が消えると**なぜ撤回したかが読めなくなる**ため。
**同一性(`truth_px` が L6 と129コマ一致)は生きている** —— **算術の問題ではなかった。**

### 画素の読み方(納品の注意をそのまま持つ)

**値は `255 - 被覆` で、色ではない。** 白く塗った面も黒く出る(`用紙` と同じ)。
したがって `gray<128` は「墨」ではなく **「その層が塗った範囲」**。

これは目的に対してむしろ正しい。`keep4` が答えるのは **「この層は面か線か」**で、
**「この層はベタか」ではない。** 面であってベタでないもの(背景ベース面、白塗り)は
面として出る。それを混ぜないため、ベタかどうかは別の列で持つ。

### 量(回す前に固定)

```
keep4(層) := |fill_mask(層の被覆)| / |層の被覆|
fill_mask: ink = cov>50% ; core = ink & (dist_to_bg > 4) ; fill = (dist_to_core <= 4) & ink

### 2. 測る量(回す前に固定)

予測側は **L7 と同一・無改変**: `pred(コマ) = fill_mask_4( ink_of(データセットの線画ラスタ) )`。

```

面:   R_pred = pred の連結成分(>=500px) / R_true = truth の連結成分(>=500px)

**面単位を主役に置く**のは、J の結論が「判断の単位は面」だったから。

### L14 の結論

1. **作者の工程は正しい。** 原寸で2例とも、ベタレイヤ上の細い印が線の隙間をなぞって
   塞いでいるのが見える。工程2・工程3 は実在する (P24 PASS)
2. **我々の逆算は、工程2の痕跡が消えているために届かない。** 隙間埋めの印は、その直後の
   塗りつぶしに**飲み込まれてベタの一部になる**。完成したベタレイヤから拾えるのは
   「はみ出した分」だけで、それが腕2 が +0.013 しか動かなかった理由である
3. **残る問題の大きさは測れた。** 線だけから塗りつぶすには、ベタ輪郭の **2-5割**、
   **1領域あたり 5-8本、1本 22-30px** の、線に裏打ちされていない区間を**全部**
   予測しなければならない。1つ外せば 256倍に漏れる
4. したがって「面を予測する」問題は「**閉じた輪郭を予測する**」問題と等価で、

### §1 問い (ユーザーの提案から)

L17 の結論は **「ベタは線を1層に絞らない(q1 0.2565/0.2933 対 棒 0.5672/0.5779)。

### §2 母集団と器具

母集団は L17 と同一(作者のコマの中の 1,563 面、うち置ける 608/919)。**単位が変わる**:
測るのは面ではなく****門が通した層の墨**(コマの中)の8連結成分**(以下 成分)。

```
seed(R)   = ∂R から 4px 以内の**門が通した層**の墨 (L17 の adj。D1=4)
label(R)  = adj の argmax 層 (L17 と同じ。**名前はラベルで、母集団の選別には使わない**)
prop(R)   = seed(R) に触れる墨の8連結成分の和集合
cov1      = ∪_R prop(R) の画素 / コマの**門が通した層の墨**   (**P36 の 9.2% と同じ分母**)
comp_pur(C, L) = |C ∧ L| / |C|                 C は成分、L は C が受け取った語の層
```

複数の面が同じ成分に別の語を付けたときは**競合**として別に数える(§4 の開示)。

### §3 **先に縮退を測る。これが答えの大半かもしれない**

L17 の教訓(縮退の点検は**測る単位**で行う)。伝播の場合の縮退は**成分が巨大**なこと:

- コマの**門が通した層の墨**の**最大成分が占める割合**の分布
- **1つの成分が跨ぐ作者レイヤの数**の分布(`z_global` で最上位に割り当てた後)
- 成分の画素数の分布

**もし成分の中央が既に3層以上を跨いでいるなら、伝播は語を運べない**(`comp_pur` が
構造的に低い)。**その場合 L18 は「縮退のため測定にならない」で閉じる**。
これは**棒の前に印字し、基盤に送る**。

### §4 棒の形 (**定数は基盤が決める。こちらは走らせてから読まない**)

- **P38 被覆**: `cov1 >= f(cov0)`。`cov0` は対照(面をコマ内で平行移動、seed 5本)。
  **伝播は定義上 seed を含むので `cov1 >= 0.092` は自明。棒は帰無値の関数でなければならない**
- **P39 伝播の正直さ**: `share(comp_pur >= 0.90) >= g(帰無値)`。
  **成分の画素数で重み付けた値を併記**(大きい成分が少数で支配するため)
- **P40 開示(棒なし)**: 競合(1成分に2つ以上の語)の数と画素
- **P41 開示(棒なし)**: 成分の大きさで層別した `cov1` と `comp_pur`

**感度**(判定に使わない): 伝播を**測地距離 g ∈ {∞, 512, 128, 32}px で打ち切る**格子。
`g=∞` が登録の一次。打ち切ると被覆は下がり `comp_pur` は上がるはずで、
**UI の設計(どこまで自動で伸ばすか)はこの曲線から決まる**。

### §5 既知セル (別プロセス。PASS しなければ本体は起動しない)

- **KC21 合成**: 2本の弧が交差して1成分になるとき `comp_pur` が画素比に一致(±0.02)。
  1本だけなら 1.0000
- **KC22 合成**: `prop` が seed を含む8連結成分**ちょうど**で、触れていない成分を含まない
- **KC23 データ経路**: `prop ⊇ seed` が全面で成立。`cov1` を別経路で数えて一致
- **KC24 データ経路**: コマの**門が通した層の墨**の総和が L17 の P36 の分母
  (**ako6 43,279,719 / ako7 45,598,813 px**)と一致

### §6 これで何が決まるか

- **被覆が 9.2% → 3〜4割に伸び、`comp_pur` が高い** なら、**UI の1クリックが線の束ごと動く**。
  UI 案の価値が一段上がり、L17 の FAIL は「ベタは語を与える、ただし伝播が要る」に変わる
- **伸びない、または伸びた先が層をはみ出す** なら、**UI はベタ周辺の局所作業に留まる**。
  その場合でも L17 の数(1頁 6面・8割が2択)は UI 設計に使える

**どちらでも設計が決まる。** L17 と違い、**FAIL が道を閉じない**形の問いである。
