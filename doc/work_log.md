## 【2026-10-04】実験 H2: 既製の顔検出器でコマの顔を見つける — 小規模な試し(事前登録・結果未見)

### 目的
「顔の領域」を機械的に得られるかの見極め。得られれば、顔の中のまとまりだけを対象に
目・鼻・口・眉・耳を位置関係で分けられる。**今回は検出器が線画コマで使い物になるかだけを見る**(顔パーツの判定はしない)。

### 手順(固定)
- 検出器: 公開モデル `deepghs/anime_face_detection` の `face_detect_v1.4_s`(YOLOv8s、ONNX)。
  閾値は配布元の既定 **0.307**(threshold.json)、NMS IoU 0.7、入力長辺 640(レターボックス)。
  **つまみは結果を見て動かさない**
- 入力: コマの線画 PNG(`../lineart/dataset/<source>/line/<name>`)。外部モデルは目印付けの補助であり、
  語彙や生成モデルの学習には使わない
- 対象コマ: panel_pack 全コマから **seed 20261004 の一様無作為 40 コマ** + 陽性対照 2 コマ
  (p1874 = 閉じた目の傾いた顔、p4549 = 耳)
- 図: コマ線画に検出枠(赤)と信頼度を描く。コマ番号・作品名つき。
  出力 `results/h2_face_detect_smoke_20261004/`(montage 1 枚 + 検出一覧 csv)

### 道具確認(不合格なら止めて相談)
1. **線画 PNG とストローク座標の対応**: 各コマで、ストロークの点が PNG のインク(<200)から 3px 以内に
   ある割合。「そのまま」と「転置」の両方を測り、**良い方の中央値 ≥ 0.8** かつ向きが全コマで同じこと
   (Track G の「PNG は転置されている」が要再検証のままなので、ここで決着させる)
2. 検出器が動いていることの確認: 真っ白な画像で検出 0 個

### 判定
ユーザー目視: 42 コマについて「顔があるのに枠がない(見逃し)」「顔でないのに枠がある(誤検出)」を数える。
基準(事前固定): **見逃しが顔の 2 割以下かつ誤検出が枠の 2 割以下なら「使える」**として全コマに広げる案を起案。
外れたら、検出器の別版・頭部検出器・人手で顔枠を付ける案を相談する(このコマ群で閾値を合わせ直さない)。

### 目的

### 向きの定義(固定)
- まとまりの全線分について、線分の向き φ(画像の座標。0° = 水平、90° = 垂直)を**長さで重みづけて平均**する。
  向きは 180° で同じなので 2φ で平均する: 主方向 θ = ½·atan2(Σ L sin 2φ, Σ L cos 2φ)、揃い具合 c = |Σ L e^{i2φ}| / Σ L(0〜1)
- 特徴は (c·cos 2θ, c·sin 2θ) の 2 つ。顔の傾きは補正しない(枠は水平・垂直のみ)

### 比べるもの(H4 と同じ 1 個抜き・近傍 5 個の多数決、学習用のみ、`unsure` を除く)

- **D 位置+大きさ+向き**: (u, v, log r, c·cos 2θ, c·sin 2θ)。各軸を学習用の標準偏差で割る

### 頭の向きを計算で推定する仕組みの案(H9b の下書き。2026-10-12。向きの目印が付いてから、測り方を事前登録して確かめる)

**考え方**: 頭を球とみなす。球の中心 = 頭の枠の中心、半径 = 頭の枠の辺の半分。顔は球の表面の一部で、顔の中心は「顔が向いている方向」に球の中心からずれて見える。
- 左右のずれ a =(顔の枠の中心 x − 頭の枠の中心 x)/(頭の枠の幅 / 2)≈ k · sin(左右の角度)
  → 左右の角度の推定 = asin(a / k)。a の符号が向き(左 / 右)、大きさが正面・斜め・横顔の度合い
- 上下のずれ b =(顔の枠の中心 y − 頭の枠の中心 y)/(頭の枠の高さ / 2)≈ b0 − k · sin(上下の角度)
  → 上下の角度の推定 = asin((b0 − b) / k)。b0 は、正面・水平の顔で顔が頭の中心より下にある分(頭頂の髪の分)
- 幅の縮み: 顔の枠の幅 / 頭の枠の幅 ≈ r0 · cos(左右の角度)。横を向くほど顔の枠が細くなる。符号は出ないが、ずれ a と独立な手がかりになる
- 定数は k、b0、r0 の 3 つだけ。学習用の顔から決める

**弱いと予想される所**: 髪の量や束ね髪で頭の枠の中心がずれる。コマの端で頭の枠が切れる。後ろ向きは顔が検出されないので対象に入りにくい。
上下(煽り・俯瞰)は、髪型の影響が左右より大きいはず。

**補助の手がかり(検出器を使わないもの)**: 顔の枠の中の線の左右対称さ(正面は対称、横顔は非対称)。線の量の左右の偏り。

**確かめ方の骨子**(詳細は目印の数を見てから事前登録する): 学習用で向きの目印がある顔だけで、
(1) a の符号と左右の目印の一致率、(2) |a| と幅の縮みが 正面 < 斜め < 横顔 の順に並ぶか、(3) b と 水平 / 煽り / 俯瞰 の関係、
(4) 陰性対照: 頭の枠を別の顔のものと入れ替えると一致率が偶然の水準に落ちる、
(5) 推定した向きを H7 の手がかりに足したとき、眉・鼻の復元率が H8 の「正解の目」の場合に近づくか(横顔でも効くかが要点)。

### 実験 H9b: 顔の枠と頭の枠から頭の向きを推定する(2026-10-12 事前登録。向きの目印がまだ学習用 8 顔しかない時点で書く)

**ユーザーの感触(2026-10-12、H9a の図を見て)**: 正面・水平・横顔・俯瞰・やや俯瞰など、かなりの精度で判定できそうな予感がする。

**実行の条件**: 学習用で向きの目印がある顔が 60 以上になったら 1 回実行する。そのときの `labels/face_groups.jsonl` の行数を記録する。検証用のレコードは読み込まない。

**手がかり**(頭の枠は H9a と同じ検出器・同じ対応づけ):
- a =(顔の枠の中心 x − 頭の枠の中心 x)/(頭の枠の幅 / 2)。正 = 顔が画面の右に寄っている
- b =(顔の枠の中心 y − 頭の枠の中心 y)/(頭の枠の高さ / 2)。正 = 下に寄っている
- rw = 顔の枠の幅 / 頭の枠の幅、rh = 顔の枠の高さ / 頭の枠の高さ

**測るもの**
1. 左右の別: 斜め・横顔の顔で、a の符号と目印の左右(右向き = a > 0 と予想)の一致率
2. 左右の度合い: 正面 / 斜め / 横顔 の 3 択(後ろは数だけ報告して除く)。手がかりは (|a|, rw)。
   当て方: クラスごとの平均にいちばん近いものを選ぶ(各手がかりは全体のばらつきで割る)。シリーズ群を 1 つずつ抜いて学び、抜いた群で当てる
3. 上下: 水平 / 煽り / 俯瞰 の 3 択。手がかりは (b, rh)。当て方は 2 と同じ
