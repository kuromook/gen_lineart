## 2026-09-13 次の一手#1: 削除オラクルの目視確認 — 「攻めすぎ」で「ズレ」ではない

対象: 群A(`lineart_family`、192枚)、前処理器`lineart_coarse`。
条件画像はTrack Bの`results/holdout_validation_20260912/conditioning/`
(既に生成済み、480×480)をそのまま再利用、GTは共通基盤
`dataset/pairs_480/{train,test}/line/`。

### 実装

最初にストローク(連結成分)単位の削除オラクルを試したが失敗した:
条件画像の連結成分ごとに「GTインクを2px膨張した領域とのオーバーラップが
閾値以上なら成分ごと残す」という方式で組んだところ、f1が**前処理器単体
(0.3164)を下回る値(0.2384〜0.43、閾値を振っても天井0.74に遠く及ばない)**
になった。原因はオラクルの構成が違うこと——本来の天井0.7425は**画素
(Cannyエッジ点)単位**で「マッチしたら残す」というオラクルで、部分的に
正しいストロークの正しい部分だけを残せる(部分点)。成分単位の二値
残す/捨てるはこの部分点構造を破壊し、閾値未満の成分を丸ごと失うか
閾値以上の成分の誤った部分まで丸ごと残すかのどちらかになる。

`doc/initial_notice.md`記載の天井(0.7425)を実際に再現する構成——
`bipartite_match_f1`(`tools/pair_extraction/tile_region_manifest_480.py`)
のマッチング処理をそのまま流用し、マッチした条件画像側エッジ画素だけを
残す——に作り直した
(`results/oracle_visual_check_20260913/build_oracle.py`)。
可視化のためレンダリング時のみ1px膨張(スコアリングには使わない)。

### 結果

192枚全体:

| | f1 | precision | recall |
|---|---:|---:|---:|
| 前処理器単体(このバッチでの再測定) | 0.3164 | - | - |
| **画素単位削除オラクル** | **0.6765** | 0.9948 | 0.5255 |

`doc/initial_notice.md`記載の値(base 0.3231, oracle 0.7425, precision 1.0,
recall 0.604)と方向・桁は一致するが値はやや低い(条件画像バッチが
Track Bの生成物の再利用で、当時の測定と全く同一の実行ではないため。
追いかけて一致させる価値はないと判断——目視確認が目的であり、数値の
完全再現ではない)。

CSV: `results/oracle_visual_check_20260913/scores_per_tile.csv`(192行)
モンタージュ: `results/oracle_visual_check_20260913/montage.png`
(f1の最低・25%・中央値±10・75%・最高の7枚を条件画像/オラクル/GTの
3列で並べたもの)

### 目視結果: オラクルはGTと構造的に一致している(「ズレ」ではない)

モンタージュを見た。**画素単位オラクルは破線状(マッチした点だけが
点在)になるが、その点が辿る経路はGTの線と明確に一致している**——
顔の輪郭・鼻筋・首・箱の稜線など、複雑な線でもオラクルの残存点が
GTの対応する線をなぞっている。f1が最も低い1枚(`lineart_003_000`、
f1=0)は構図の補助線(パース取り)だけの下絵でGT自体がほぼ空白の
退化ケースで、ズレの証拠ではなくどちらも「線がない」ことの一致。
それ以外の6枚(f1 0.62〜0.94)はいずれも、オラクルが拾った点が
視覚的にGTの構造と対応しており、**「オラクルが攻めすぎている」のでも
「そもそも下絵とGTがズレている」のでもない**。

### 判断: このtrackの前提は崩れていない。Track Dへの一報も送った

`doc/initial_notice.md`の警戒(オラクルがGTとズレて見えたらペア品質を
疑う)は今回は発動しなかった。**群Aについては、ペアの対応関係自体は
健全に見える**——残差は本当に「取捨選択」の問題であって、教師信号
(前処理器のどのストロークがGTとマッチしたか)を疑う理由は今のところ
見当たらない。

これはTrack Dの仮説3(ペア対応の質)に対する**弱いが方向性のある反証**
であり、Track Dの第一報(VAEラウンドトリップ天井、まだ未着手)を
待たずに共有する価値があると判断し、`outbox/`経由で共通基盤とTrack Dに
一報した(`note_oracle_visual_check_pairs_look_sound_20260913.md`)。
ただし**この確認だけでは決定力がない**(画素単位の部分点構造ゆえ、
ズレていてもある程度は「それらしく」見えてしまう可能性は残る)ので、
Track Dの結論を上書きするものではないと明記した。
