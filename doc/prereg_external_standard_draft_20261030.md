## Question

**「線画らしさ」として測っている各軸は、作者の線画と、作者を知らないモデルが出した線画を分けるか。**

「いいえ」で答えられる —— **どの軸も分けない**ことがあり得る。その場合、
**それらの軸は「線画かどうか」を測っているだけで、「この作者の線画かどうか」は測っていない。**
**それを最適化しても作者は出てこない**、と言える。

### なぜこの問いか

いま「線画らしさ」の尺度は**全部この作者の原稿から出ている**。だから
**作者固有の性質と、線画一般の性質を分ける材料が無い。**
**外から来た線画は、この一点でだけ原稿より強い。**
(Track J が面について「残る道は面提案器と**外部標準**」で終わったのと同じ形。)

## Primary value

**軸ごとの AUC** —— タイル1枚を単位に、**作者側 = 1 / 外部側 = 0** としたときの
その軸単独の順位付け性能。**1軸につき1つの数**。

- **世代ごとに別の行で読む。世代は畳まない**(`ako6` と `ako7` を1行にしない)。
  **畳むのは軸の中だけで、世代の上では畳まない**
- **AUC を主値に選ぶ理由**: 軸ごとに単位が違う(px・比・エントロピー)ので、
  **中央値の差では軸をまたいで比べられない。** AUC は単位に依らない
- **2026-08-05 の走行との連続のため、中央値の対も隣に印字する**(あの走行は中央値で書かれている)
- **畳まないもの**: 世代、プール(作者 / 外部)、正規化の有無
- **畳むもの**: タイル(軸ごとに AUC 1つ)

## 正規化 —— **ここが設計の本体。走る前に1つに決める**

**作者の原稿は 600dpi・7016×6543 相当の CSP 出力、外部は 1024 前後の RGB。**
**素のままなら、どんな軸でも AUC 1.0 で分かれる。それは絵の話ではない。**

**登録する正規化(1つだけ)**:

1. 両側とも**短辺を同じ長さに**落とす(値は §9 で決める)
2. 固定の閾値 **128**(この企画が全体で使っている墨の閾値)で読む。**閾値を側ごとに変えない**
3. **タイルの切り方を両側で同じにする**(枚数・重なり・捨て方)
4. **寸法・dpi・ビット深度・ファイル名・圧縮痕を使う軸は、名前で除外**(腕 A1 の理由)

**代替の正規化は、いま名前を書いて、感度の腕として登録する** ——
(i) 線幅を揃えてから測る / (ii) 両側を `LineartDetector` に通す(= A2/NC4)/
(iii) 短辺を別の長さにする。
**走った後に「こっちの正規化の方が分かれる」で選び直したら、棒を動かしたことになる**(規律9-5)。
**前後の枚数を、落とした理由ごとに名前を付けて印字する**(規律9: 選別は測定である)。

## Pass criteria

**`null` = 腕 A3(`ink_ratio` 単独の頻度表)の、その世代での AUC。**

### C1 —— **一般の軸**: `AUC ≤ null + 0.05`

**その軸は「線画かどうか」を測っているだけで、作者の情報を持っていない。**
→ **その軸を最適化しても、この作者の線画には近づかない。**
**損失に入れるなら「崩れていないことの見張り」であって、目標ではない。**

### C2 —— **作者固有の候補**: `AUC ≥ null + 0.15` **かつ NC2・NC3・NC4 を通る**

- **NC2 を通る** = 世代ではなく作者を読んでいる
- **NC3 を通る** = 生成の設定ではない
- **NC4 を通る** = ラスタの工程ではない
→ **その軸は作者固有の情報を持つ。** 外部標準として意味があり、**ここから先が使える材料**。

### C3 —— **どの軸も C2 を通らない**

→ **「線画らしさ」の計測一式に、作者固有の内容が無い。**
**これはこの線の仕事が間違っていると言う結果であり、書く。**
**その場合に残る道は、軸を足すこと(いまの一式の外)か、作者固有性を画素の軸で測るのをやめること。**

### 判定保留の帯 —— `null + 0.05 < AUC < null + 0.15`

**判定保留は正直な結論である。** 「棒に届かなかった」と「判定できなかった」は別。**両方書く。**

### 棒が動いたと見なす形(先に書く)

- 走った後に**正規化を選び直す**
- 走った後に**タイルの枚数や捨て方を変える**
- 走った後に**世代の畳み方を変える**
- **`null + 0.05` / `null + 0.15` を動かす**

**どれも、向きがどちらでも棒を動かしたことになる**(曝露も母集団も棒の一部)。

## What this run cannot settle

- **作者の線画の方が「良い」とは言わない。** 分かれるかどうかだけを測る
- **SD の線画を学習の対(ペア)に使ってよい、とは言わない。** これは**対を作らない**測定である。
  対を作る話は**関係が逆向きになる**ので、別の登録が要る
- **分かれる軸が、そのまま損失に使えるとは言わない。** 判別できることと、
  微分して最適化できることは別で、**一指標最適化 → 線画性崩壊**はこの企画が繰り返してきた形
- **面(塗り)については何も言わない**
- **`stroke_decomposition.py` はここでは使えない** —— あれは
  **条件画像と GT の対**を要求する(A/B/C の分割が対から定義される)。
  **外部標準には対が無い。** 使えるのは**対を要らない軸だけ**で、それが `measure_lineart_profile.py`
- **外部の1モデルについてしか言わない。** 「SD 一般」には広がらない(NC3 がその境界を測る)

### **裁定を受けて測ったこと —— 1,489 は独立な 1,489 ではない**

既存の CSV の `sample` 列を数えた(**主値ではない。母集団の構造である**):

| | 数 |
|---|---:|
| タイル | **1,489** |
| **相異なる元のコマ/頁** | **457** |
| 1つの元から 1枚 / 2枚 / 3枚 / 4枚 | 69 / 46 / 40 / **302** |
| 作品(= このプールに在る層別の軸) | **5**(536 / 455 / 202 / 164 / 132) |

**効き方**:

1. **帯をタイル単位で計算すると、精度を約 1.81倍(`√(1489/457)`)過大に書く。**
   **帯は元のコマ単位で引く**(元でまとめた bootstrap)。**タイル 1,489 と 元 457 を両方印字する**
2. **「外部側も同じ枚数」は、タイルで合わせるだけでは構造が合わない。**
   **推奨: 外部側も 457枚生成し、同じ配り方(1枚×69・2枚×46・3枚×40・4枚×302)で 1,489タイルに切る。**
   こうすると**両側の塊の構造が同じになり、「同じ元から来たタイルは似ている」で分かれる道が塞がる。**
   1画像1タイル(1,489画像)でも n は正直だが、**構造が片側だけ違う**ので、こちらは勧めない
3. **層別の軸は「年」ではなく「作品」である。** このプールに在る札は作品名5つで、
   **IC2(既知セルは世代ごとに1つ)はこの5つの上で引く。**
   作品を年に対応させるなら **census の領分**(こちらで名前から決めない)
4. **主値は「作品 k vs 外部」の5行で読む。** 作品の大きさが 536〜132 と違うので、
   **行ごとに帯の広さが違う。行ごとに印字する**
5. **NC2(作者 vs 作者)は作品の間で引く**(5作品で10対)。
   **NC2 は本命より n が小さいので帯が広い。** 「NC2 が分けなかった」は
   「本命が分けた」より弱い証拠になる —— **比べるときは n を揃えて(本命を間引いて)比べる**
6. **NC3 には2つ目のチェックポイントの 1,489タイル(= 457画像)が要る。**
   **生成は合計 914画像。** 3060 で収まる量である
