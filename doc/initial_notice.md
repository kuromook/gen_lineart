## この track の目的

**線画を線の集まりとして取り出すときの「つながり」を正しくする。** 線の精細化でも生成でもない。

発端はユーザー(2026-10-16、Track H で 300 顔の単語入力を終えた直後):
> 「線の1PX化と接続によって、つながりがおかしいパーツがかなり多い」

この欠陥は **Track F / G / H の全部より上流**にある。単位(パーツ=語)がそこで決まるので、
語の信頼性・顔パーツの確定・配置の構造はすべてこの欠陥を継承している。

## つながりの誤りは 2 方向ある。混ぜない

| | 意味 | 作者の印 | Track J の測定 |
|---|---|---|---|
| **過接続**(over-merge) | 別々のものが 1 本につながっている | **ある**(「解体する線」`broken`) | ベタ近傍で骨格がベタの中心軸になる |
| **過分割**(under-connection) | 1 本の描線が複数に切れている | **ない** | **腕の 18.7% しかつながらない = 律速** |

**いまデータがあるのは過接続だけで、律速なのは過分割**である。これを最初に分けておく。

## ゼロからではない —— 既にある測定値

### 現行の接続規則(Track F `tools/stroke/strokes.py`、読むだけ)

1px 骨格 → 交差数で分割(3x3 膨張してノードに) → 自由端のヒゲを剪定(`spur_max=6`、局所インク幅も下限)
→ 太い交差の内部の短い橋をノードに畳む(局所インク幅の 1.5 倍) → **各ノードで腕を
「出射方向のなす角が 180° に最も近い順」に貪欲に対にする**(`max_bend=35°`、`reach=10px`、`min_len=8`)。
対にならなかった腕はそこで終わる。

→ 見ているのは**接線の角だけ**。横ずれ・線幅の連続・骨格より前の元インクは参照していない。

### Track J 連鎖器(2026-10-10、較正済み・対照付き。`doc/work_log.md` 1158-1330 付近)

- 線画で腕の **7,513 / 40,212 = 18.7%** しかつながらない(ラフ 6,812 / 54,573 = 12.5%)
- **IC-j6**(実インクに人工的に線を引いて切り、つなぎ直せるかをラベル付き標的にする。
  較正用と測定用はパネル番号で機械的に分離): rejoin **0.654** / wrong **0.039**
- **交差点では曲率は情報を持たない**。`W_KAPPA=0` が最良、20px 窓の曲率は量子化ノイズ。
  効くのは**接線の一致と横ずれだけ**
- **細線化は交差点中心に線を引き寄せるので腕の先端は変形している**。先端 2px を飛ばすと
  再現率はほぼ不変(0.657→0.654)で**誤接続が 0.104→0.039**
- **ベタの近傍では骨格はそもそも描線ではない**(長く滑らかな鎖がベタの中心軸として出る)。
  ベタになった髪の輪郭をなぞる線は、骨格ではなく**領域の輪郭**から取る必要がある
- J の登録済み次手:「つなぎ直せなかった 34.6% のうち、損益分岐(2.0)で**拒否された**ものと
  **別の腕に誤って**当てられたものの比」。直し方が違うので先に分ける

### Track H「解体する線」の実績(105 顔時点、2026-10-12 の事前登録集計)

- `broken` の項目がある **74 顔のうち、印が 1 本以上ある顔は 42(57%)**
- 印は **90 本**。その 74 顔の線 10,204 本の **0.9%**。うち **65 本がパーツのグループの中**
  (グループにした線の約 3%)、25 本はグループの外。1 顔あたり 1〜3 本が大半、最大 7 本
- **本番の最初の 23 顔と試しの 5 件は `broken` の項目がない。これは「印を付ける手段が
  なかった」であり「解体する線がない」ではない。** 集計で必ず区別する

→ 「かなり多い」は、**顔単位では過半(57%)、線単位では 0.9%**。どちらも同じ事実の別の量。

## 的: 「正しい接続」の GT をどう作るか(着手前に主要評価指標を登録する)

1. **人工切断**(IC-j6 の型、既に動く): 真値が構成上わかる。弱点は切断の分布が実際の交差と違いうること
2. **作者ラベル**(H の型、作者律速で高価): 過分割の印は**まだ存在しない**。頼むなら
   「このグループの線は、本来もっと少ない本数で描かれているか」のグループ単位の二値が最小の形
3. **再描画の自己一致**(転置・50px ずらし・再縮尺): GT 不要だが**安定性の検査であって
   正しさの検査ではない**。正しさとして読んではならない

自明な腕(これに勝てなければ何も言えない): **全く繋がない** / **全部繋ぐ** / **現行の Track F 規則**。
基盤 lesson 6「評価のベースラインは常に前処理器」が、ここでは
「ベースラインは常に現行規則」という形で効く。

## 事前登録(2026-10-16。Track H の 300 顔分析の結果を見る前に書いた)

**K1: 過接続の印は、ベタ領域に隣接する線に偏る。**
根拠は Track J の「ベタ近傍の骨格は描線ではなくベタの中心軸」。顔は髪のベタを伴う。
- 対象: Track H の `labels/face_groups.jsonl` のうち **`broken` の項目があり、かつ学習用で完了**の顔のみ
  (H6 と同じ切り方。検証用は読まない)。印のある線 vs その顔の残りの線の 2x2
- ベタマスクは Track J の `tools/evaluation/fill_mask.py`。**隣接の閾値は測定前に決めて印字する**
- 器具確認: (a) ベタマスクの面積割合を顔ごとに印字し、Track J の母集団の分布と桁が合うこと
  (b) 陰性対照 —— 印の本数と同数の線を同じ顔から無作為に選んだ偽の印では偏りが出ないこと
  (c) ベタがほぼ無い顔を除いたときに結論が変わるかを別行で出す
- **反証されれば原因は細線化一般の側にあり、直し方が変わる**(ベタ近傍の輪郭取得では済まない)
- 作者の時間は **0**。既にあるデータだけで測れるので、これが最初の一手

## 範囲 —— 細線化そのものを問い直してよい

1px 化は「線を単位にトークン化する」ために選ばれた表現であって目的ではない。
線幅を捨てない折れ線表現、ベタ近傍で領域の輪郭から取る経路、骨格を作らずインクと距離変換だけで
扱う案を同じ土俵に乗せてよい。ただし勝敗は上の主要評価指標と自明な腕で決める。
