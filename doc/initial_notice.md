## 4. L の最初の仕事: 器具点検。そして**双方向**である

**抽出側の判定規則には形の項が無い** —— 色の純度・量・紙面の暗さだけ。
だから**「純黒のベタ」と「アンチエイリアス無しの1bit線画」を区別できない**。
抽出側自身が 2026-10-23 に数で裏づけた: 部位名の層124枚中**63枚が純黒**だが、
その `drawn_ratio` は**中央値0.0004**(ページの0.04%)で、**在庫の窓(>=0.01)に入るのは3枚だけ**。
**これは面ではなく線。** そしてこの指摘は 781層にもそのまま当たる。

**基盤が manifest 側で測った範囲**(実験ではなく目録の検査):

| | 値 |
|---|---|
| 納品781層の `drawn_ratio` | p10 **0.00226** / 中央 **0.00431** / p90 **0.02298** / 最大 0.3964 |
| うち 0.01 未満 | **75.7%** |
| 純黒の部位名層(63枚)の `drawn_ratio` 中央 | **0.00045** |

**納品の下限0.002が、1bit線画の大半(中央0.00045)を既に落としている。** だが
**0.002を超える密な線画層は落とせず、納品の75.7%が重なりうる帯にいる。**
**大きさは形ではない** —— 0.5%を覆う細い線の束と0.5%の塊は同じ数字になる。

**こちら側が持っている器具が、まさにその形の試験である**:
`../lineart-solid-fill/tools/evaluation/fill_mask.py` の
`fill = (core までの距離 <= 4) & ink`、`core = ink & (背景までの距離 > 4)` ——
**半径4の円が入る領域だけが残る。ストロークは落ち、面は通る。**

> **抽出側は色を試験し、L は形を試験する。どちらも他方から作られていない。
> だから一致は情報になり、不一致は「どちらを見るべきか」を示す。**

当初心配した循環はこれで解ける(測っている軸が違う)。**両向きに読むこと**:
- 制作層にあって半径4マスクが拾わない面 → **マスクを見る**
- 制作層にあって形の試験を通らない層 → **抽出側の選択を見る**(1bit線画の混入)
- マスクが拾って制作層に無い面 → どちらか。ページの版を先に固定して切り分ける

**J の全数値がこの半径4マスクを継いでおり、マスクは一度も外部標準と照合されていない。**
L はその照合を初めて行う位置にいる。**J が求めたのは一致だけでなく誤差の向き**である
(膨らんでいるのか欠けているのか)。

## 5. 照合の前に固定すること(全部 2026-10-23 に判明した罠)

1. **照合対象は「ページ」ではなく「ページのその版」。** コマ・コーパスは同じページを
   複数の作画段階で持つ。`ako6` は227コマ中**150枚(66%)が複数版グループの中**。
   `ako6/page0051_p1` は墨率0.1907、`done/ako6-3_p1` は0.0067 ——
   **一方はベタが入り他方はほぼ白紙。** 未完成版に制作層を当てると
   「マスクが面を全部取りこぼした」と読めてしまう。**版は `manifest.csv` の `slug` と
   `content_fingerprint` で区別できる**(指紋は版ごとに別値、pid跨ぎ共有ゼロ)
2. **完全複製が held の 2.0%**(8組19コマ)。train/held 跨ぎは**0**(漏洩なし)。
   点検は `../lineart-solid-fill/tools/evaluation/audit_koma_duplicates.py`
3. **カラーはページの性質で、作品の性質ではない。** 除外は**ページ単位**で、
   `../lineart/inbox/work_color_mode_pages.csv`(1,348行)を使う。作品単位の列は47作品で誤る
4. **半径4の意味はコマによって違う。** コマの一辺が約900〜4,600pxとばらつき、半径4は原寸に
   当たっている。制作層はページ座標(`ako6` は 7016x6543)。**尺度の補正はL側の仕事**で、
   一致/不一致を読む前に片付ける。`sens_fill_radius.py` に半径3と6の感度行がある
5. **原稿側の重複**: 289作品の実体は**270**(13グループ・19作品ぶんが年フォルダ跨ぎ)。
   `../lineart/inbox/work_duplicates.json`

- **`all_black`(全部塗る)の micro IoU = GT のベタ面積比と同一の数**:
  0.0939(housei test n=782) / 0.1201(ako5 held n=474)
- **`blank`(塗らない)の region-F1 = 0.0084**(956コマ normal 層)。
  **J の最良腕は 0.0110 で、その差は +0.0026 しかない**
- **`all_black` の pixel IoU 0.1040 は、学習済み M0(0.0204)/M1(0.0124)の5〜8倍**
- **ベタではベースラインが前処理器ではない**(前処理器は0を取る)。対になるのは
  **塗らない / 全部塗る**
- **プールを跨いで平均しない**(ベタ面積比 housei 3.21% 対 ako5 10.28%、3倍違う)

## 7. 登録の作法 —— この木が継ぐ規則(全部 2026-10-23 に稼いだもの)

1. **事前登録。結果を見た後で棒を動かさない。母集団や曝露を広げるのも同じこと**
2. **「単純な方で足りる」は2つの事態に同じ文を出す。** 判定文には**自明な腕の点を同じ文に持ち**、
   最良腕が自明な腕を登録余白で越えていなければ、見出しは
   **「この定式化ではどの腕も課題をこなさない」**とする(「学習モデルは要らない」ではない)
3. **名前で数えた在庫は、その名前が指すものの在庫ではない。** 署名を現物の側で確認するまで
   標準として引用してはならない
4. **点検の名前は、その点検が何を見ているかを名乗らねばならない。** 在庫の名前は数が合わなければ
   露見するが、**点検の名前は何も報告しないのが正常動作なので露見しない**
5. **鍵・名前・区分は含意を持つ。含意は点検ではない。性質を直接試験せよ**
6. **代理で絞った時は、代理が外した側の説明がつくまで閉じない**
7. **層の数は制作の作法を測っており、中身を測っていない**
8. **スクリーニングの数は何も順位付けしない**(構成は標本の大きさ)
9. **信じられる範囲の数字が返ることは、その器具がその対象を測った証拠ではない。**
   「この器具は物理的に何に取り付いているか」を問う
10. **対照は、試験する1軸だけで違わなければならない**
11. **数値は構成とセットでしか引用できない。** 母集団も、それが母集団であった測定とセットで
12. **新しい測定は既知セルを1つ含める。再現しなければ他を読まない**
13. **撤回は項目ではなくパス。** 同じ作業の中で全ての置き場を直す
14. **絵が何を描いているかは作者が決める**(規律6)。モンタージュで論じず原寸の切り出しを出す
