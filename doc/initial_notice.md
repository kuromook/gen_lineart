# Track G: コマ生成 — concept を与えて単語を配置して「描く」

作成: 2026-09-21 JST / ブランチ: `panel-generation`
起案: `../lineart-stroke-grammar/outbox/track_g_generation_proposal_20260921.md`(承認済み)
前身: Track F `../lineart-stroke-grammar`(線の文法。測定フェーズ完了で封存)

このファイルは「現状・次の一手・運用ルール」だけを短く保つ。
実験の時系列は`doc/work_log.md`に追記すること。

## この track が存在する理由

Track F(線の文法)で5つの測定がすべて一致し、**「コマ内の単語間文法」は見つからなかった**:

1. 自己回帰モデル: 7.35 (unigram) から 6.94 bits/語 しか改善しない(門 6.85 で僅差不合格)
2. bigram (7.40) が unigram より悪い = 正準順序の隣接性に情報が無い
3. set-cloze: 7.398 bits で unigram にも届かない(門 6.35)
4. ショット型12個を条件にしても 7.312(改善 0.036 bits のみ)
5. WD14タグ40個を条件にしても 7.370(改善なし)

一方で Track F が確立した資産:
- **単語は実在する**(500語 FSQ、細部除去で 23.2% 変化、使用率 92%、D=0.166)
- 単語の**空間配置**には構造がある(位置予測が周辺分布 7.56 を 6.31-6.39 に下回る)
- 単語の内側の構造は強い(B′選択 0.662、細部不変性、19/20 語に人間が名付け可能)
- コマの**場面型**(12クラスタ)が人間に場面記述として命名できる単位

**結論: 生成は「文法が単語列を引き受ける」形では組めない。
concept(場面)を外部入力として与え、文法(モデル)の役割は
「その concept の下で、どの単語をどこに置くか」の選択と配置に限定される。**

## 目的

**与えられた concept(場面型/タグ、将来的には下絵やテキスト)に対して、
単語を空間に配置し、コマの線画を生成する。**

GPT たとえの整合性: Track F は「単語の並びが文法に従う」と仮定したが、
実際の漫画は「作者が描こうとしていることが文(=絵)を決める」。
つまりこちらは**条件付き生成の track**であり、無条件の「文章生成」ではない。

## 5P/5C: 絵の構成を決める10要素(操作定義・Track F 2026-09-21 に確立)

ユーザーによる洞察: **線画を単語の配置として読むとき、配置を支配しているのは
10の構成要素である。これらが未定義なら、配置は無軌道に見える。**
この track ではこれらを**特徴量として定義し、生成・評価・語の解釈のすべてに使う。**

| 要素 | 意味 | 操作定義 | 状態 |
|---|---|---|---|
| **composition** 構成 | コマのショット型 | per-コマ特徴量(単語数・密度・scale分布・plane割合・単語ヒスト・タグ)をk-means | ✅ Track F で実測。12型が人間に場面記述として命名可能 |
| **placement** 配置 | 語どうしの相対位置 | 語ペアの相対位置分布(型ごと) | ⬜ この track で実装 |
| **plane** 面 | コマ枠・面の処理 | コマ枠に張り付くまとまりの割合 | ✅ 特徴量として Track F で実装済み |
| **perspective** パース | 奥行きの記法 | 長い直線の収束度(消失点の有無・強度)。counter と幾何基盤を共有 | ⬜ この track で実装 |
| **proportion** 比率 | 部品の大小関係 | まとまりのスケール分布(12ビン) | ✅ 特徴量として実装済み |
| **pose** 姿勢 | 人物の姿勢 | 部品語の配置から姿勢を読む(placement の応用) | ⬜ この track で実装 |
| **counter** 線の質 | 線の画風・リズム | 集中線ではなく**線の質**: 曲率分布・直線区間割合・線幅変動・点間隔の周期性 | ⬜ この track で実装 |
| **character** 個性 | 作品・作家の画風 | 顔部品語の再帰的出現から「キャスト」(登場人物の絵柄)を発見 | ⬜ 将来 |
| **coodinate** 統一感 | 作品内の一貫性 | **1作品・シリーズ単位**での上記統計の一致度。混合コーパス全体では測らない | ⬜ この track で実装。work 列で作品識別可 |
| **concept** 構想 | 何を描くか | **測定対象外**。条件付け入力として与える(WD14タグ・12型が代理) | ✅ 外部入力として位置づけ済み |

## 設計の柱

1. **語彙は Track F の資産をそのまま使う**:
   `../lineart-stroke-grammar/results/invariance_20260920/l4_w500/codebook2.pt`
   (500語・回帰復号・levels 5,5,5,4)。単語の細部は残差 stage が保持する2段構造。
2. **生成器の形**(測定結果が示す三分割に対応):
   - **選択**(どの単語が現れるか): concept 条件 + 既置単語からの set-cloze 型。
     予測可能性が低い(7.31)ので、尤度最大化ではなく「もっともらしい単語集合のサンプリング」。
   - **配置**(どこに置くか): 条件 + 既置単語から (pos_y, pos_x, scale) を予測。
     構造が最もある(6.31-6.39)。**生成の主力**。
   - **細部**: 符号化器/復号器が引き受ける(生成側の責務は置き方だけ)。
3. **評価は事前登録制**:
   - 描画して目視(鉄則)
   - 線の統計(長さ・密度・交点)の分布一致
   - 破片化指標(捕捉率・1本あたり交点数)で「崩れた出力」でないこと
   - 条件一致: 与えた concept のタグが生成コマに現れるか
4. **禁止事項(Track F から継承)**: 480pxタイル不使用(絵の単位はコマ)、
   下絵不使用(初期)、合成負例による判別を主軸にしない、
   事前登録した基準の事後緩和禁止(厳しくする方向は記録の上で可)、
   数値には必ず目視モンタージュを results/ 配下に併記。

## 積み上がりのロードマップ: ピースは相互に強化する

**前提**: 今埋まっているピースは全体の一部に過ぎない。
- **単語の名づけは道半ば**(頻出上位20語中19語まで。残り480語は未命名)。
- **5P/5C 特徴量は composition/plane/proportion しか実装されていない**(7要素は将来)。
- **細線化(分かち書きの前段)もまだまだ改善の余地がある**。

**相乗効果**: ピースが埋まるほど残りのピースは簡単に埋まる曲線が予想される。
- counter(線の質)が入れば、見た目が似て線質だけ違う単語の区別と名づけがしやすくなる
- 名づけが進めば、型の解釈と placement の分析が正確になる
- 細線化が改善すれば、単語の切れ目が正確になり、語彙・配置・counter のすべての測定が正確になる

**姿勢**: はじめはしんどいが、ねばり強く1ピースずつ埋める。
急いで全体像を仕上げようとせず、測定→記録→次のピースの順で確実に積む。

## 運用ルール(Track A〜F で確立、継承)

- **戦略ラベル(2026-09-24 ユーザー決定)**: 戦略上重要な単語(当面は顔パーツ: 目・鼻・口・眉・耳)には、
  人が**戦略ラベル**を割り当ててよい。これは機械の語 ID(`wNNN`)とは**別の名前空間**で管理し、
  戦略に応じて使う・使わないを実験ごとに事前登録で明示する。戦略ラベルは正解データとして
  定量評価に使ってよい(従来の「命名は解釈用であり定量判定に使わない」の例外。一般の命名は従来どおり)
- **cluster_set meta の列名は逆**(Track F `results/cluster_set_20260919/meta.csv`): `cy` 列 = x、
  `cx` 列 = y。strokes/pts は (x, y) 順、corpus dims は (H, W)。corpus の位置ビンは
  py = x/H・px = y/W で作られており歪んでいる(2026-09-23 発見。work_log 参照)
- **数値だけで判断しない。** 必ず目視モンタージュを作り、画像の正確なパスを数値と併記する。
  画像は`/tmp`ではなく`results/`配下
- **プールを跨いで平均しない**
- **学習損失で進捗を判断しない**
- 大きな学習・抽出は必ずスモークテストしてから本番投入
- 長時間GPUジョブは月〜木の4日連続バッチが標準枠
- バックグラウンド実行は`setsid`で切り離す(PPID=1を確認)。`pkill -f <スクリプト名>`は
  自分のシェルにも一致して自滅するのでPIDを特定して`kill`する
- 待機ループの`until ! pgrep -f <名前>`も**ループ自身のコマンド行に一致する**ので終わらない。
  文字クラスで自分を外す
- 目視モンタージュの窓を「最も密な所」で選ぶと必ずベタ・調子が映る。線の領域を見るには
  中位の密度の窓も併せて出す
- **新しい数値が出たら必ず「これは道具を測っていないか」を疑う**
  (この系列は測定の道具そのものが壊れる失敗を6回している)

### 1. 軸の不具合: 本trackの 2026-09-23 の診断は**原因が誤り**でした(ただし歪みは実在)

Track H が 2026-10-04 に、解析系の外にあるもの — 線画PNG
`../lineart/dataset/<source>/line/` — と 42コマで照合して決着させました。

- **`meta.cy` は y、`meta.cx` は x。列名のとおりで、入れ替わっていません。**
- 転置されているのは1階層下: **`strokes.npy` / `cluster_set` の `pts` が (y, x) 順**
  ((x, y) と読むと点がPNGのインクに乗る割合は中央値 0.11、(y, x) なら 0.999)。
- **corpus の `dims` は (W, H) の順**。
- 「元の線画PNGは転置されて保存されている」(9/23 の副次的発見)も**撤回**。PNG は正立です。

**歪みの指摘は有効です。** corpus の位置ビンは `py = cy/dims[0]` = y/W、
`px = cx/dims[1]` = x/H。どちらの読み方でも分母が食い違うので実際に歪んでおり、
最上位ビンの飽和16〜20%(一様なら6.25%)も、位置ビット系の数値
(7.563 / 6.315〜6.388 / 6.658)がその上に乗っていることも、そのままです。

### 2. 本trackの GT 解析は**数値は正しく、軸の名前だけ入れ替わっています**

共通基盤が 2026-10-09 に `tools/gen/placement_gt.py` を読んで確認しました。

```
x = meta.cy  (実体は y)  を  Wd = dims[1]  (実体は H)  で割る → y/H  ← 正しい比
y = meta.cx  (実体は x)  を  H  = dims[0]  (実体は W)  で割る → x/W  ← 正しい比
```

**2つの取り違えが打ち消し合っています。** 層2・層3 の正規化位置、距離、
対称な統計量はすべて有効です(再計算は不要)。ただし:

- **`x` と呼んでいる軸は実際には y**、`y` と呼んでいる軸は実際には x。
- したがって**向きを読む記述はすべて対角線で鏡像**です — 上下/左右、角度の符号、
  「この語の上にある語」。層3の相対ベクトル `(dx, dy)` も名前が入れ替わっています
  (反射なので距離は保たれ、方向の意味だけが入れ替わる)。
- 図を再び作るときは、必ず**線画PNGとの照合**を道具確認に入れてください。
  同じ座標系どうしの一致は向きを保証しません(共通基盤 lesson 12。Track H は
  この誤りで全図が鏡像になり、「線に乗る割合 1.00」の確認と陰性対照の両方を通過しました)。

### 3. 本trackが中断した問いに直接関わる Track H の結果(2026-10-04 / 10-09)

本trackは「配置は絶対座標でなく相対位置で決まる」(ユーザーの主張)を測ろうとして
器具チェックに3回失敗し、顔パーツで先に測るよう Track H に渡しました。その結果:

- **語はパーツの同一性を持っていません**(共通基盤 lesson 13)。作者が付けた
  目印1,003個で、学習用の1個抜き比較: **位置+大きさ**が目(開)0.66/0.78・口 0.66/0.74
  (基準率 0.27 / 0.14)に対し、**語だけ**は目(開)0.60/0.50 でそれ以外はほぼ無力、
  **位置+大きさに語を足すとどの目印でも悪化**。学習用223個が79語に散り最頻語11個。
  → 「語を選んで置く」という本trackの枠組みのうち、**何を描くかを語IDが決めるという前提**は
  このままでは成り立ちません。
- **まとまりという単位が混ざっています**: 顔パーツを含む575個の41%が混在
  (眉は75%が髪と同じまとまり)、全線の14.6%はどの候補にも入っていません。
  → 本trackが「語の信頼性 = 境界の安定性で、意味の混ざりは測れない」と書いた点の、
  測定された形です。Track H は現在、単位そのものを作り直す(線単位の正解を作る)段階にいます。
- **一方で、相対位置の構造は「枠に対する相対座標」で素直に出ます**: 顔検出枠の中の
  (u, v) の密度に、**左右の目の2つの山**((0.27, 0.40)・(0.73, 0.38))、**口の山**
  ((0.50, 0.73))、r<0.1 で**鼻の位置の縦長の山**が現れました。顔検出器は外部モデル
  (`deepghs/anime_face_detection` v1.4_s、既定閾値、目印付けの補助のみ・学習には不使用)で、
  42コマの作者判定で誤検出なし・見逃し15%、5,345コマの71%で顔を検出しています。
  → **この枠は、本プロジェクトが初めて手にした「混ざった語ではない参照枠」**です。
  相対位置を測り直すなら、基準語ではなく枠を参照にするのが第一候補になります
