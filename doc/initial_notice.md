## 4. 守る規則(基盤から持ち込むもの)

- **正規化が設計の本体。** 素のままなら解像度・線幅・アンチエイリアス・キャンバス寸法で
  **どの軸も AUC 1.0 で分かれる。それは絵の話ではない。**
  **正規化は1つだけ登録し、代替は感度の腕として名前を先に書く**
- **走った後に正規化・枚数・捨て方・世代の畳み方・棒を選び直したら、向きがどちらでも棒を動かしたことになる**
- **判定保留は正直な結論である。** 「棒に届かなかった」と「判定できなかった」は別。両方書く
- **選別は測定である。落としたものを理由別に名前を付けて数えて印字する**(器具の中の `continue` にも当てる)
- **世代もプールである。** `ako6` と `ako7` を1行にしない
- **評価のベースラインは常に前処理器(`LineartDetector`)**。腕 A2 がそれ
- **絵が何を描いているかは作者が決める**(規律6)。疑わしいときは原寸の切り出しを出す

- **1枚の形**: **480×480、グレースケール(mode `L`)、JPEG**
  (量子化表の先頭 `[2,1,1,2,2,4,5,6]`。PIL の quality 95 相当。**走る前に厳密に確かめること**)
- **元のコマは 457個**。1つの元から 1/2/3/4枚 = 69/46/40/302

### **ここから出る、正規化の必須条件が1つある**

**作者側は JPEG で、外部側は普通 PNG で出てくる。**
**JPEG の輪(リンギング)は線の周りの faint 画素を作るので、
`faint_of_drawn_ratio` / `faint_near_ink_ratio` / `faint_mean_dist_to_ink` が
「絵の違い」ではなく「圧縮の違い」で分かれ得る。**
**2026-08-05 の走行で一番大きく分かれた軸が `faint_near_ink_ratio`(0.899 対 0.663)である**ことに注意。

> **外部側も、同じ JPEG の経路を同じ品質で通してから測る。**
> **または両側を同じ設定で入れ直す。どちらかを選んで、走る前に書く。**

**これを飛ばすと、一番効きそうな軸が圧縮を読んでいることになる。**
