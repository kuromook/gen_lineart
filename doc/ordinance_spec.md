# 条例の型 —— 各 track の個別法

提案: `ops-review`、2026-10-30 / **正本に入れるのは基盤**(規律3)
実例はこの木の `doc/initial_notice.md § 条例`、器具は `tools/hooks/session_brief.py`

## なぜ型を決めるのか

**条例は既に 8 本の track に在る。足りないのは型だけ**(`doc/ops_review_proposal_20261030.md` §0-2)。
型を決めると3つ効く:

1. **節名が1つになるので、器具が抽出できる。** いまは「守るもの」「やらないこと」
   「禁止事項」「守る規則」「登録の作法」「守ること」「運用ルール」の**7通り**
2. **番号で引けるので、通達が全文を写さなくなる。** 写しが増える原因は「引けないこと」
3. **抽出できれば SessionStart で注入できる** —— 条例が基本法と同じ**常に在る**層に上がる

**層の話である**(ここを間違えると skill に置きたくなる):

| 置き場 | いつ読まれるか | 誰が決めるか |
|---|---|---|
| `CLAUDE.md`(基本法) | **常にコンテキストに在る** | ハーネス |
| **条例(いま)** | セッションの最初 —— 基本法 §0 が読めと命じていて、その命令が常時在る | ハーネス(命令経由) |
| **条例(注入後)** | **常にコンテキストに在る** | ハーネス |
| skill | description が合うと**モデルが判断したときだけ** | **モデル** |

**skill にすると一段下がる。** 条例を skill に置いてはいけない理由はこれで、配布の話ではない。

## 型

### 節名は `## 条例`。**固定**

器具との唯一の接合部なので、綴りを変えない。
(`T108`: 再利用した器具の唯一の継ぎ目はキーの名前だった)

### 中身は4つ。この順

```markdown
## 条例

**上位法**: 規律は `../lineart/doc/CURRENT.md § Working Discipline`、運用は
`../lineart/CLAUDE.md`。**この木の `CLAUDE.md` は branch 時点の複製なので読まない**(T92)。

**判定の単位**: <絵を判定するのか / 部品(面・線・層)を判定するのか / どちらもしないのか>

1. <その track でしか導けない規則。禁止には**反証条件**を添える>
2. <引用してはいけない数と、その理由>
...
```

### 書かないこと

- **基本法の写し。** 指し手だけ置く。**凍っても害が無いのはこれを守るからである** ——
  写しが在ると T84/T92 がそのまま効く(`fill-region` が手で差分を維持していた実例)
- **現在地・経路・履歴・数値の表。** それらは引き継ぎの他の節と `doc/work_log.md`
- **他の track の規則。** 借りるなら相手の `条例N` を指す

### 引用形式

track の中では **`条例3`**。外から引くときは **`fill-region 条例3`**。
(`規律N` が台帳の番号、`T<n>` が罠の番号。条例はその track の番号)

## 予算

**2,000 字。** 実測(2026-10-30、8 本の条例節):

| | 条例節 | 引き継ぎ全体 |
|---|---:|---:|
| `stroke-topology` | 231 | 6,620 |
| `stroke-grammar` | 262 | 15,420 |
| `ops-review`(型の実例) | 683 | 4,513 |
| `census` | 686 | 5,591 |
| `external-standard` | 1,044 | 4,733 |
| `colour-manuscripts` | 1,113 | 7,646 |
| `solid-fill` | 1,234 | 6,360 |
| `fill-region` | **1,924** | 13,809 |

**全 8 本が予算内。** 節だけ注入すれば引き継ぎ全体より **78〜98% 少ない**。
最大の `fill-region` でも `CLAUDE.md`(6,533 字)の 3 割。
**条例はもともと収まっている —— 埋まっていただけである。**

**予算を超えたら切らずに警告する。** 法を黙って落とすのは規律9 が禁じている形
(選別は測定である)。収まらない条例は**起草の欠陥**で、実行時の条件ではない。
`fill-region` は上位法の写しを抜けば大きく下がる。

### **字数 ≠ トークン。日本語はほぼ 1:1**

予算を**字数**で切ったのは、網も鍵も要らず**どの木でも `wc -m` で測り直せる**から
(`names_are_not_checks`: 測り直せない予算は予算ではない)。だが読み替えるときは:

| | 比 | 出所 |
|---|---|---|
| **英語** | **1 トークン ≈ 3 字** | `moat` の description 5本 **1,223 字** に対し台帳の実測 **常時 425 トークン**(2026-10-25) |
| **日本語** | **1 字 ≈ 1 トークン前後**(目安。実測ではない) | 漢字はほぼ 1:1、かなはやや少ない。**`**` やバッククォートの markdown 記号が別に乗る** |

**つまり予算 2,000 字 ≈ 2,000 トークンで、`moat` の約5倍、基本法の約 1/3。**
「2,000 字」と書くと小さく聞こえるが、そうではない。
**いまの実測は 820 字**で、`fill-region` の 1,924 は**写しが最も多い本**なので、
写しを指し手に替えれば下がる。**予算は上限で、実際の負荷は半分以下に収まる見込み。**

**正確なトークン数は `anthropic` SDK の `count_tokens` で確定する**(SDK は入っている)。
**外向きの呼び出しなので、叩くならユーザーの承認を取ってから。**

## 器具

### 条例を注入する

`tools/hooks/session_brief.py`(SessionStart)。`## 条例` 節だけを読み、
編集者向けの `<!-- -->` を外して注入し、字数と予算を頭に印字する。

**回した対照**(2026-10-30):

| 対照 | 期待 | 結果 |
|---|---|---|
| 条例が在る track | 節だけ注入(引き継ぎ全体は入らない) | ○ 820 字 |
| `## 条例` 節が無い | **黙らない。「無い」と言う** | ○ |
| 予算超過(2,376 字) | **切らずに警告**。本文は全部入る | ○ 詰め物 450/450 |
| `foundation` | **条例を注入しない**(基盤の法は `CLAUDE.md` 自身)。audit は回る | ○ |

### 止まっていた木を追いつかせる

`tools/catch_up.py`。**法に属するファイルだけ**を基盤の版と突き合わせ、
**木ごとに解決した命令を印字する**(T84: 直し方は文字列ではなく点検である)。
何も書き換えない —— 回すのはその木に座っている者。
`catch_up.py <道> ...` で他の木を**読み取りのみ**で一覧できるので、基盤からの点検にも使える。

**比べる相手は `origin/foundation` のような名前ではなく、基盤の木の `foundation` が指す
commit そのもの。** この器具の最初の版は名前で比べて `lineart-face-words` の `.gitignore` を
**「同じ」と報告した** —— その木の `origin/foundation` は **346 commit 遅れ**で、
`data/` 規則が入っていない版と一致していただけである。**T84 を器具が再生産していた。**
いまは**法の現在の commit がその木に無ければ、一件ずつの比較を出さない**
(出すと「同じ」が嘘になる)。

**回した対照**: この木(基盤 +1 commit)→ 追いついている・exit 0 /
`stroke-selection`(25日止まっていた)→ **6 件遅れ**を実在の sha つきで印字・exit 1 /
`face-words`(別クローン、346 commit 遅れ)→ **比較を拒否し fetch を促す**・exit 1。

**休止した track が復活するときに最初に回すのがこれである。**

## 手順(その木で回す。**6手**)

**基盤は配るだけ。回すのはその木に座っている者である** —— 法のファイルを書き換えるので、
作業中の変更の上では回さない。

```bash
# 0. 作業中のものを片付ける(`git status --porcelain` が空になるまで)
# 1. 法の版を見る(**読み取りのみ。何も書き換えない**)
#    **`venv` はこの木に無いことが在る**(2026-10-30: 6木のうち3木に無い)。
#    無ければ基盤の実体を絶対パスで: /home/sh1/deepl/lineart/venv/bin/python
/home/sh1/deepl/lineart/venv/bin/python /home/sh1/deepl/lineart/tools/catch_up.py
# 2. 印字された per-file の命令を回す(自分の側の変更が在るファイルだけ先に diff で読む)
# 3. `.claude/settings.json` を取ったら **`/hooks` を一度開く**(でなければ効かない)
# 4. `doc/initial_notice.md` に `## 条例` 節を書く(この文書の型。写しを置かず指し手だけ)
# 5. 確かめる
/home/sh1/deepl/lineart/venv/bin/python tools/check_public_artifacts.py   # 期待 exit 0
/home/sh1/deepl/lineart/venv/bin/python tools/catch_up.py                # 期待「追いついている」
# 6. commit して push(**push は track 自身**)。基盤に1行返す(条例の字数)
```

**`git merge foundation` で済ませない。** 法のファイルは5〜13 件なのに、merge は
`doc/CURRENT.md`(4,400 行)と `doc/work_log.md`(16,500 行)を連れてくる ——
**`ops-review` の枝で、衝突が1つも出ないまま作業ログが 16,391 → 530 行に潰れる形が実証済み。**
**「衝突が無いこと」は「安全であること」ではない。** だからファイル指定で取る。

**器具は引数が無ければ「いま居る木」を見る**(`git rev-parse --show-toplevel`)。
2026-10-30 に直した —— それまでは**器具が在る木**を見ていたので、基盤の実体を絶対パスで
呼ぶと**基盤自身を点検して「追いついている」と答えた。** 呼んだ人は自分の木について
聞いたと読む。**別の木を見たいときだけ道を渡す**(`catch_up.py <道> ...`、読み取りのみ)。

**`.gitignore` は、取る前に必ずその木の行を読む。** 2026-10-30 に基盤が Track M で踏んだ ——
M の `.gitignore` には **`labels/*.jsonl.orig`(作者の答の別名化の前の控え。原稿の固有名を含む)**
が在り、**基盤の版にはそれが無かったので、取った瞬間に保護が外れた**(実体が7件、
`git status` に現れた)。**`git diff <法の sha> -- .gitignore` の自分側の行を読む。**
落ちるものが在れば**取らずに基盤へ上げる**(この件は正本へ上げたので、いまは取ってよい)。

**自分の側の変更が在るファイルは、取る前に読む。** `catch_up.py` は「分岐」までしか言えない
(**木の大半がこの状態**)。見分けるのは `git log <法の sha>..HEAD -- <道>` ——
**その木の commit が 0 本なら写しが古いだけ**で、在るならその commit を読んでから決める。
**法のファイルがその木で良くなっていることも在る**(2026-10-30、`census` の器具が持っていた
原稿 DB の規則を正本が持っていなかった)。**その場合は取らずに基盤へ戻す** ——
正本の著者は基盤なので、基盤が採ってから配り直す。

## 移行

**動いている track だけ。遡らない。**
**ただし終了・休止した木も、復活するときは `tools/catch_up.py` で追いつける**
(法のファイルを配る案 (a) は rebase しない木に届かないので、器具の側で埋める)。

| | いまの節名 | 作業 |
|---|---|---|
| `census` | 守るもの / やらないこと | 節名を `## 条例` に。規律9 の写しを指し手に。番号を振る |
| `colour-manuscripts` | 作者の判断 / 規律 | §6「規律」は**既に指し手付き**なので写しを落とすだけ。作者の判断の表は条例の本体 |
| `external-standard` | 守る規則(基盤から持ち込むもの)/ 画素と重み | **節名が「持ち込む」と言っている** —— 7項の大半が写し。指し手に置き換える |
| `fill-region` | 登録の作法 | **写しが最も多い**(`CLAUDE.md` §3 の一行を手で追跡している)。指し手にすると予算に余裕が出る |
| `solid-fill` / `stroke-topology` | 禁止事項ほか | **休止中。再開するときに** |

**終了した 9 本は触らない。** 「運用ルール(Track A/B/C で確立、引き継ぎ)」節は
**記録**であって運用文書ではない(T92: 送った手紙は記録)。
**節名が複製を意味することだけ台帳に書く。**

`CLAUDE.md` §5 の「track の文書は2本だけ」は**変えない。**
条例は `doc/initial_notice.md` の中の節で、新しいファイルを作らない。
