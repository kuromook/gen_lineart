# 聞き取りの UI の指針(2026-11-07)

**状態: 2026-11-07 にユーザーが確認(§7 の2点を含む)。** 共通の部品は `tools/ui/`(使い方は `tools/ui/README.md`)。
**出所**: ユーザーへの聞き取り(2026-11-07、下の §0)と、これまでの事故(lesson 11 / 2026-10-26 の
「何について答えるのか」/ 規律6)。既存の UI: Track L の `tools/ui/l19_*` `l38_*`(取り消し・保留・
キーボード・補間なしの表示あり)/ census の `tools/census/ui_template.html`(拡大縮小なし)/ Track E の判定画面(artifact)。

## 0. 位置づけ

**UI は聞き取りの器具である。** 向きを与えるのは人の判定で(第1条)、それを集めるのが UI。
**混乱を招く UI は、誤って測る器具と同じ** —— 答えが問いではなく画面の作りを測る。

**ユーザーの答え(2026-11-07)**
- 困ったこと: **絵が収まらない・拡大できない / 何を答えるのか分からない / 選択肢が合わない・直せない**
  - 分からなかったもの: **どの層・面のことか / 選択肢の言葉の意味 / 答えた後どうなるか**
  - 合わなかったもの: **当てはまる選択肢が無い / 一言添えたいのに書けない**
- 端末: **LAN の別の端末からも**答える —— **キーボード付きの PC とタブレット(タッチ)**
- 最初の表示: **画面に収めて、必要なら拡大**
- 1回の長さ: **短く(数分・数十問)**

## 1. 問いを画面に書く

1. **問いを1文で、画面の上に固定して書く。** 判定の単位(絵1枚 / 層 / 面)を問いの中に書く
2. **対象に印を付ける。** 合成した絵なら、**合成前の層を並べ、問う層・面を輪郭か色で示す**。
   対象以外を薄くする切り替えを置く
3. **選択肢は作者の言葉で書く。** 器具の用語(`stratum`、`v_layer_kind` など)を画面に出さない。
   各選択肢に1行の説明を付ける
4. **「この答えで何が決まるか」を1行書く**(例:「この答えで、この層を面の境界に使うかが決まる」)

## 2. 選択肢

1. **「どれでもない」と「分からない」を必ず置く。** 無理に近いものを選ばせると、偽の答えになる
2. **どの答えにも一言を添えられる欄を置く**(任意)
3. **「どれでもない」や一言が多く来たら、問いの作りの欠陥として記録する**(作り手の負け。答えは直さない)

## 3. 絵の表示

1. **最初は画面に収める。** 拡大縮小は、**ホイール / ピンチ / キー**(`+` `-`、`0` = 収める、`1` = 等倍)。
   ドラッグかスワイプで移動
2. **拡大は画素を補間しない**(`image-rendering: pixelated`)。**縮小には使わない** —— 補間せずに縮めると細い線が点線のように途切れる
   (2026-11-07、部品の試験で器具自身が起こした。縮小は滑らかに縮める)。**いまの倍率を画面に出す**
3. **縮小すると細い線は消える。** 線の有無を問うときは、等倍の確認を促す一言を置く
4. **タッチでは、ピンチは絵の中だけに効かせる**(ページ全体を拡大させない)

## 4. 操作

1. **キーボード**: 数字 = 選択肢、`Enter` = 次へ、`←` = 前へ、`z` = 取り消し。
   **キーはボタンの上に書く。** 文字を打っている間はキーの割り当てを止める
2. **タッチ**: ボタンは指で押せる大きさ(44px 以上)
3. **前に戻って直せる。直しは新しい行を足し、前の行は消さない**(Track L の形)

## 5. 長さ

1. **1回は数分・数十問で区切る。** 途中でやめても、続きから始められる
2. **残りの数を画面に出す**

## 6. 保存

1. **1問ごとにすぐ保存する。追記だけで、上書きしない**
2. **行に残すもの**: 問いの ID / 見せた絵の ID と版 / 答え / 一言 / 時刻 / UI の版
3. **同じ問いをもう一度出せる作りにする**(本人内の一貫性を測るため。Track E の門の「再掲」)

## 7. 置き場と公開(**2026-11-07 ユーザーが決定**)

1. **LAN の端末から答えるので、待ち受けは LAN に開いてよい。インターネットには出さない**
   (ルーターで外から入れない。`0.0.0.0` で待つなら、そのことを起動時に印字する)
2. **claude.ai の artifact で聞き取ってよい。原稿の画素を含んでもよい。ただし使い捨てにする** ——
   ユーザー:「**聞き取り artifact は残すと数が増えそうなので使い捨てにしたい(聞き取り終わったらデータは残して削除)**」
   - **答えは artifact の外に必ず移してから消す。** 移し先は聞いた track の `data/`(原稿の名前を含むなら追跡しない)。
     **移した行の数を artifact 側の行の数と突き合わせ、一致を印字してから**消す
   - **消すのはユーザーの確認を取ってから**(artifact の削除は取り消せない)
   - 作った artifact の URL・作った日・消した日を、聞いた track の `doc/work_log.md` に1行ずつ残す
     (残っている artifact が増えていないかを後から数えられるように)

## 8. 作者に出す前の点検

1. **作り手が自分で3問を通しで答える**(端末2種: PC のキーボードとタブレット)
2. **画面の問いの1文だけを読んで、何に答えるか言えるか**を確かめる
