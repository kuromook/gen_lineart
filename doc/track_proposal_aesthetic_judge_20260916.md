# Track E 起案: 「線画らしさ」の審判を作り、食い違う場所をそこに委ねる

起案: 2026-09-16 / 起案元: `lineart-pair-signal`(Track D、診断完了)
きっかけ: ユーザーの問い「GTでも条件画像でもなく、ベースモデルの絵が持つ**美**に寄せる作り方はないか」

## なぜこの track が要るのか

Track D が測った通り、**画素の一致を目的にする生成の学習は、条件画像の再現に収束する**。
条件画像に無い GT の線を描く割合は、位置の合ったペアで学習しても対照と同じ約10%だった。
一方で、出力の線の 27〜50% は **GT にも条件画像にも近くない**——凍結 UNet の癖(クロスハッチ、
描き足した髪の線)である。つまり「ベースモデルの美」は**すでに出力に混ざっているが、誰も制御して
いない**。本プロジェクトはそれを一貫して「幻覚」として扱ってきたが、**それが常に悪いのかは
一度も確かめていない**。

食い違う場所(GT と条件画像が一致しない領域)は、現状どの目的関数も定義していない空白地帯である。
ここを「人が見て良いと思う方」に倒せるなら、Track C の選択にも、生成の微調整にも使える。

## この track の問い

**「線画として良い」を、人の判断を再現する形で採点できるか。**

できたら、次の3つに接続できる(この順に安い):
1. **Track C の同点決着**: 条件画像の線を残すか消すかで GT が答えを持たない場所の判断
2. **推論時の空間制御**: 条件画像が当てにならない領域だけ ControlNet 強度を下げ、癖に任せる
3. **報酬による微調整**(DRaFT/ReFL 系): 採点器を報酬にして数ステップ分だけ逆伝播する

## 段取り(この順。1 が終わるまで 2 以降に進まない)

### 1. 判定データを集める

素材はすでにある。Track D のスナップショット出力(2つの学習 × 5〜11時点 × 192タイル)と、
前処理器単体・削除オラクル・GT。ここから 2 枚組を作り、**どちらが線画として良いか**を選んでもらう。

- 比較 UI は Artifact で作る(選択結果を保存する機能つき)。1回の判断は数秒、目標は 300〜500 組
- 同じ組を再提示して**本人内の一貫性**を測る(採点器の上限はここで決まる)
- 「どちらとも言えない」を選べるようにする。曖昧な組は学習から外す

### 2. 採点器を作り、検証する

- 入力は 480px タイル1枚、出力はスカラー。まずは既存の線画らしさ軸
  (`near_white_frac`/`line_width_p50`/`fill_ratio`/連続性/交点統計)を特徴量にした軽い線形モデルから
- 次に小さな CNN(または CLIP 特徴 + 線形)。**hold-out の人の判断をどれだけ再現するか**だけで評価する
- **合格条件を先に決める**: hold-out 一致率が、本人内一貫性の 85% 以上。かつ、
  既存の単独指標(f1 / near_white / fill)より明確に高いこと
- **落ちた場合の扱いも先に決める**: 合格しなければ 3 以降には進まない。指標に 3 回裏切られた
  プロジェクトなので、ここで止まれることが設計の一部

### 3. 用途に接続する(合格後)

- まず Track C の同点決着(学習不要、判断の差し替えだけ)
- 次に推論時の空間制御(学習不要)
- 最後に報酬微調整。ここで初めて学習が要る

## 測る基準

| 段階 | 判定 |
|---|---|
| 1 | 300組以上、本人内一貫性が測れている |
| 2 | hold-out 一致率 ≥ 本人内一貫性 × 0.85、既存単独指標を上回る |
| 3 | Track C の指標、または holdout 192 の目視比較で改善が見えること |

## 範囲外

- **採点器が段階 2 に合格するまで、生成モデルの再学習はしない**
- GT を置き換えることではない。GT が答えを持つ場所は今まで通り GT に従う
- 「美」の一般論ではなく、**この線画データセットに対するこのユーザーの判断**を再現する

## リスク

- **報酬ハッキング**: 採点器を報酬にすると、その弱点を突く出力に収束する。段階 3 では必ず目視と
  既存の複数軸を併記する(教訓 2・3・6 がそのまま効く)
- **ラベル収集の負担**: 300〜500 組の判断。1組数秒でも 30〜60 分は要る
- **少数の好みへの過適合**: 判定者が1人である以上、汎化は主張しない

## Track D からの引き継ぎ

- 線単位の測定道具(`stroke_churn.py`、`output_vs_condition_proximity.py`、
  `pair_alignment_strata.py`、`fixed_t_validation_loss.py`)はそのまま使える
- 「出力の線は条件画像から引き継がれる」「損失は紙の白さしか追わない」は前提として扱ってよい
- 未解決で引き継ぐもの: 規模(仮説5)、potential のデコーダ感度、manga_line の空白化の原因
