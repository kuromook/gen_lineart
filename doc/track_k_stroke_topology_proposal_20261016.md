# 新 Track 起案(案): 線の接続 — 1px 化が壊した「つながり」を直す

日付: 2026-10-16 / 起案: Claude(ユーザー所見を受けて)
状態: **未承認**。承認されたら新ブランチ `stroke-topology` を切り、本草案を
`doc/initial_notice.md` として転記する。
発端: ユーザー(2026-10-16、Track H で 300 顔の単語入力を終えた直後)
> 「線の1PX化と接続によって、つながりがおかしいパーツがかなり多い、これらは対処すべき課題だ」

## なぜ別 track か

この欠陥は **Track F / G / H の全部より上流**にある。単位(パーツ=語)がそこで決まるので、
語の信頼性(G)・顔パーツの確定(H)・配置の構造(F/G)はすべてこの欠陥を継承している。
いま誰も本格的に持てない:

- **Track F**(`lineart-stroke-grammar`)が現行の 1px 化と接続規則の所有者だが、
  2026-09-21 に封存済みで**ファイルを改変しない**という拘束がある。読むだけ
- **Track J**(`lineart-solid-fill`)は連鎖器でこの問題そのものを測っているが、
  本務はベタ塗りで、連鎖器は並行の副業
- **Track H** は作者律速。ラベリングを止めてはいけない

## ゼロからではない —— 既にある資産

### 1. 現行の接続規則(Track F `tools/stroke/strokes.py`、読むだけ)

1px 骨格 → 交差数で分割(3x3 膨張してノードに) → 自由端のヒゲを剪定(`spur_max=6`、
局所インク幅も下限) → 太い交差の内部にできた短い橋をノードに畳む(局所インク幅の 1.5 倍)
→ **各ノードで腕を「出射方向のなす角が 180° に最も近い順」に貪欲に対にする**
(`max_bend=35°`、`reach=10px`、`min_len=8`)。対にならなかった腕はそこで終わる。

つまり現行規則が見ているのは**接線の角だけ**である。横ずれ・線幅の連続・元のインク(骨格より前)は
一切参照していない。ユーザーが見た「つながりがおかしい」は、この規則から予測できる形をしている。

### 2. Track J 連鎖器の測定値(2026-10-10、較正済み・対照付き)

- **接続率が律速**: 線画で腕の **7,513 / 40,212 = 18.7%** しかつながらない(ラフは 12.5%)。
  つまり大半の腕は「誤接続」ではなく**接続されずに切れている**
- **IC-j6(実インクに人工的に線を引いて切り、つなぎ直せるかをラベル付き標的にする)**で
  到達性能 rejoin **0.654** / wrong **0.039**。較正用と測定用はパネル番号で機械的に分離
- **交差点では曲率は情報を持たない**。`W_KAPPA=0` が最良で、20px 窓の曲率は量子化ノイズ。
  効くのは**接線の一致と横ずれだけ**
- **細線化は交差点中心に線を引き寄せるので、腕の先端は変形している**。先端 2px を飛ばして
  当てはめる(`TAN_SKIP=2`)と再現率はほぼ不変(0.657→0.654)で**誤接続が 0.104→0.039**。
  これは「変形した最後の数 px が、間違った腕を共線に見せていた」という意味
- **ベタの近傍では骨格はそもそも描線ではない**: 長く滑らかな鎖がベタの中心軸として現れる。
  ベタになった髪の輪郭をなぞる線は、骨格ではなく**領域の輪郭**から取る必要がある
- Track J の登録済み次手: 「つなぎ直せなかった 34.6% のうち、費用の損益分岐(2.0)で
  **拒否された**ものと**別の腕に誤って**当てられたものの比」。直し方が別なので先に分ける

→ この track は**較正済みの器具とラベル付き標的の作り方を引き継いで**始められる。
連鎖器の所有権を J から移すか、J に残して結果を共有するかは承認時に決める。

## 本当の難所: 「正しい接続」の GT が無い

接続の正しさを測る真値は、現時点でどこにも無い。ここを曖昧にしたまま改良を始めると
「max_bend のスイープ」に縮む。候補は 3 つで、**結果を見る前に**どれを主要評価指標にするか登録する。

1. **人工切断(IC-j6 の型、既に動く)**: 実インクに自分で線を引いて切り、つなぎ直せるか。
   真値が構成上わかる。弱点は「自分で作った切断」が実際の交差の分布と違いうること
2. **作者ラベル**(H の型、作者律速で高価): パーツ単位で「つながりが正しいか」の二値。
   300 顔はすでに作者が 1 つずつ見た唯一の母集団で、**二値フラグの付け直しは 300 回の yes/no で済む**。
   これが得られれば欠陥率という頻度表が手に入り、問題の大きさが初めて数になる
3. **再描画の自己一致**(転置・50px ずらし・再縮尺で接続が変わらないか): GT 不要だが
   **これは安定性の検査であって正しさの検査ではない**。正しさとして読んではならない

自明な腕(これに勝てなければ何も言えない): **全く繋がない** / **全部繋ぐ** / **現行の Track F 規則**。
基盤 lesson 6 の「評価のベースラインは常に前処理器」が、この track では
「ベースラインは常に現行規則」という形で効く。

## 事前登録する予測(2026-10-16、300 顔の分析結果を見る前に書いている)

Track J の「ベタ近傍の骨格は描線ではない」から出る予測:
**接続の欠陥率は、ベタ領域に隣接するパーツで、ベタから遠いパーツより高い。**
顔は髪のベタを伴うので、H で見つかった欠陥の相当部分はこれで説明できるはず。
反証されれば原因は細線化一般の側にあることになり、直し方が変わる。
判定には Track J のベタマスクを使い、隣接の閾値は測定前に決めて印字する。

## 範囲 —— 細線化そのものを問い直してよい

1px 化は「線を単位にトークン化する」ために選ばれた表現であって、目的ではない。
したがってこの track は**接続規則の調整に限定しない**。線幅を捨てない折れ線表現、
ベタ近傍で輪郭から取る経路、骨格を作らずインクと距離変換だけで扱う案を同じ土俵に乗せてよい。
ただし勝敗は上の主要評価指標と自明な腕で決める。
