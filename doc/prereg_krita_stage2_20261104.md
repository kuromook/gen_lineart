## Question

**Krita の配られた重み(`SketchyModel` / `SmoothModel`)を手元のラフに当てた出力は、前処理器
(`LineartDetector(coarse=True)`、以下 `lineart_coarse`)の線のうち GT に無い線(C)を、GT にある線(A)より
選んで消しているか。** —— 「いいえ」と答えうる。

**なぜこの問いか**: lineart 系の残差は**削除**である(台帳: 前処理器は GT の 1.4 倍の墨を置き、
削除だけの神託で f1 0.7425 対 0.3231)。Krita の資料が褒める性質は「重ね線を一本に・薄い線を落とす」で、
**削除の操作**として書かれている(調査書 §3)。受容野 21 px の局所フィルタ(Sketchy)が**選んで消せるか**は、
第1条の側では「人が線画として買う削除は、局所の情報で決まるのか」に答える。

## Arms

**腕の格子**(すべて印字。**一番良い腕だけを見出しにしない**):

| 軸 | 値 | 理由 |

| 入力の向き | `noinv` / `inv`(入力を 1−x、出力も 1−y で戻す。プラグインの `invert` と同じ) | 学習時の向きが**不明**(調査書 §2)。プラグインの既定は Sketchy=`noinv`、Smooth=`inv` |
| 縮尺 s | **×1 / ×2 / ×4**(ラフを LANCZOS で s 倍 → 推論 → 出力を `Image.BOX` で 480 に戻す) | 受容野は画素で固定、Krita の学習は A3 300dpi・線幅 12〜20 px で拡縮の増強なし(調査書 §2)。**縮尺は今ここで3つに固定し、結果を見て足さない** |

(`Sketchy/noinv/×1`、`Smooth/inv/×1`)。残り 10 腕は同じ表に並べ、見出しの文では
「12 腕のうち C1 を満たした数」を**プールごとに**書く。

**推論の再現**(`tools/krita/` に自分で書く。**落としたコードは import しない**、条例3):
プラグイン 1.0.2 の切り方どおり —— 16 の倍数に切り上げ(右・下を 0 で埋める)、外周を余白 40 で 0 埋め、
256 のタイル・内側 176 px を繋ぐ、`[0,1]` の float32、出力は sigmoid 値 ×255 を切り詰め。
**埋め値はモデル空間の 0**(`noinv` では黒い枠になる。調査書 §2 —— それも込みでプラグインの再現とする)。
実行は **OpenVINO 2024.5.0(プラグイン同梱と同じ版)を専用の venv `data/krita_venv/` に入れ、CPU で**。
共有の venv には入れない。重み・出力は追跡しない(条例1・2)。出力は `results/krita_stage2_20261104/<arm>/<stem>_out.png`。

**基準の腕**(moat の既定4つ):
- **何もしない** = ラフそのもの(`rough`)。測る腕
- **全部やる** = GT を出力として採点(`gt`)。**定義上 D = 1、c_survival = 0、neither_ink = 0 の恒等式**(下記 IC4)
- **既存の道具だけ** = 前処理器の素の出力(器具の `condition (lineart_coarse)` 行)。**定義上 a=1 / c=1 / b=0 / neither=0、D = 0 の恒等式**。
  下限の棒だが、**この器具の上では恒等式なので「勝った」の根拠は D の正の値だけ**
- **学習なしの安い記述子** = ラフをタイルごとの **Otsu 閾値**で二値化(`rough_otsu`)。Krita の資料が比べている
  「Levels フィルタ」の、パラメタを持たない代用

## Primary value

**D = a_recall − c_survival**(`stroke_decomposition.py` の定義、許容 2 px、`edge_map` = Gaussian σ1 + Canny 45/135)。
タイルごとに計算し、プールごとに平均。**読むのは帰無値を引いた D′ = D − D_null。**

- 意味: 前処理器の線のうち、**GT にある線(A)が残る割合**から **GT に無い線(C)が残る割合**を引いたもの。
  一様に消す操作(A も C も同じ割合で消す)は D = 0、墨を足すだけの操作(A も C も覆う)も D ≈ 0。
  **墨で買えない**のがこの値を主に選んだ理由
- **帰無値 D_null(棒の前に出す、規律9)**: 腕ごとに、タイル i の出力を**同じプールの別の元画像**のタイル j の分解で
  採点した D の平均(j はタイルごとに `random.Random(20261104)` で 1 つ、全腕で同じ j)。**予想: |D_null| ≤ 0.03**
- 平均するのはプール内のタイルだけ。**プールをまたいで平均しない。腕をまたいで平均しない。**
- **並べて印字する(基準ではないが必ず隣に置く)**: `b_recall`・`neither_ink`・`a_recall`・`c_survival`・出力の墨の画素数・
  f1(`bipartite_match_f1(edge_map(out), edge_map(gt), 2.0)`)と、その f1 の matched-null signal(lesson 9 の式)
- **比べる過去の値**(台帳 2026-10-02、lineart 系 192 タイル、生成系の腕): 表の 22 腕(9 腕は `baseline` と同一の出力で、異なる出力は 13)で
  D は **−0.0136〜+0.0174**(`plus_uniform/baseline` は 0.0169。2026-11-04 に表から計算) —— **この企画の生成系で D が 0.02 を超えた腕は無い**

## 落としたものの数え方(規律9)

器具の `nanmean` は空の分母を黙って落とすので、**腕 × プールごとに次を数えて印字する**:
出力ファイル欠落(器具の `continue`)/ 出力の edge が 0(neither が nan)/ A が空 / C が空 / B が空。
**D はタイルの A と C がどちらも空でないときだけ定義される**ので、D を数えたタイル数を必ず `n_D` として並べる。

## Negative controls

- **NC1(層: 採点の対応付け)**: 出力 i を別の元画像のタイル j の分解で採点 = 帰無値そのもの。**予想 |D| ≤ 0.03**。
  これを超えたら D は「出力の位置」ではなく「プールの墨の分布」を読んでいる
- **NC2(層: 推論の向き)**: `noinv` で学習されたモデルに `inv` を当てる(またはその逆)誤りは腕として既に在る。
  **予想: 向きを誤った側は出力がほぼ一面(墨の画素数がラフの 3 倍超か 1/10 未満)になり、D の絶対値は 0.03 以下**。
  12 腕のどちらの向きがこれに当たるかは**事前に分からない** —— それを知ることも段2 の成果
- **NC3(層: 縮尺の戻し)**: ×4 の出力を 480 に戻さず左上 480 を切って採点する誤り。**予想: D ≈ D_null(|D − D_null| ≤ 0.03)**。
  1 腕(`Sketchy/noinv/×4`)だけで回す
- **NC4(層: 外周の埋め)**: `noinv` の黒い枠が D を作っていないか —— タイルの外周 40 px を除いた D を `Sketchy/noinv/×1` で並べる。
  **予想: 外周を除いても D の差は 0.02 以下**。超えたら黒い枠の効果として別に書く

## Pass criteria(プールごと・腕ごとに判定。プールをまたいで足さない)

- **C1(選んで消す)**: D′ = D − D_null **≥ 0.10**、かつ **元画像ごとの D′ が正の元画像が lineart 系で 8 中 6 以上 / housei で 3 中 3**
  - 満たす → その腕は**前処理器の線を選んで消している**。21 px の Sketchy で満たせば「**この削除は局所の情報で決まる**」が
    仮説として立ち、段3(手元の対での学習)を基盤経由でユーザーに上げる根拠になる
  - **0.03 ≤ D′ < 0.10** → **判定保留**(棒に届かなかったが、過去の生成系の最大 0.0174 より上)。保留と書く
  - **D′ < 0.03(全 12 腕で)** → **Krita の重みは手元の対の上で選んで消していない**。資料の「薄い線を落とす」は
    手元の前処理器の過剰描画(C)とは別の物を消している、と書く。**段3 に進む根拠は無くなる**
  - **棒 0.10 の根拠**: 過去の生成系 22 腕の幅(−0.0136〜+0.0174)の上端の約 6 倍。削除の神託は D = 1
- **C2(墨で買っていない)**: C1 を満たした腕について **neither_ink ≤ 0.20**(過去の生成系 `plus_uniform/baseline` が 0.195)
  - 満たさない → 「消しているが、別の所に墨を足している」。C1 の通過をその腕の見出しに書かない
- **C3(この企画が見たことの無い形か)**: C1 と C2 を満たし、かつ **b_recall の matched-null signal > 0**
  - 満たす → Krita の重みは**消しながら描いてもいる**。Track D の「条件に無い GT の線は描かない」と逆の形で、強い主張になるので
    **原寸の切り出しで作者に見せてから**書く(規律6)
  - 満たさない → 想定どおり(21 px では B は描けない)。そう書く
- **この線そのものが間違っていると言う結果**: **IC4 の恒等式が出ない**、または **`rough` 腕か `rough_otsu` 腕が C1 を満たす**
  —— 前者は器具、後者は「D はラフの墨が前処理器より少ないことを読んでいるだけ」の意味になり、
  **D を主値に選んだこと自体が誤り**。その場合は Krita の腕を読まずに止め、基盤へ通達する

## What this run cannot settle

- **Krita のモデルが「良い」か「悪い」か**(この track の問いではない)
- **Krita の重みで出なかったことを、Krita の手法(構造・損失)が手元の対で学習しても出ないとは読めない** —— 段3 の問い
- **手元の対は両方向に緩い**(Track D)。Krita の学習の対は上描き。差の原因を**モデルと対に分けられない**
- **D は前処理器の地図に対する削除の選択性**であって、線画としての質ではない。線画として読めるかは C4 だけが言う
- **縮尺 3 つのどれが「正しい」縮尺か**は決めない。3 つとも並べる
- housei の分解には外の既知セルが無い(IC2 は GT の引き当てしか守らない)
- 受容野の違い(21 対 105)による差が出ても、**向き・損失・学習データの違いと分けられない**(どの設定で学習したか不明、調査書 §5)
