# 原稿の国勢調査 —— 集計の仕様(骨子)

**ユーザーの指示(2026-10-26)**: *原稿データの「国勢調査」は重要な情報だ。スキルと規律に
基づいて都度レイヤや原稿の情報をチェックするには重すぎる。必要な情報を集計して持っておく
ほうがいい(集計データなので github にあげも OK)。こちら(ユーザ)からすると集計を確認する
webUI などがある方がありがたい。*

**基盤はこれを実装しない**(規律5)。この文書は**何を持つか・どこに置くか・何を書き添えるか**
を決めるもので、器具と UI は track が作る。

---

## 0. なぜ重すぎたのか —— 診断

**重かったのは数を取ることではなく、数に付く但し書きを毎回引き直すことだった。**
2026-10-26 の1日で、同じ形の誤りが**14回**起きている。すべて「数は取れたが、その数が
何の数かを確かめていなかった」:

| 形 | 例 |
|---|---|
| 欄の名前が中身を言っていない | `has_mask` 全部 True(T87)/ `drawn_ratio = 0` は空ではない(T129) |
| 欄がビット列 | `visibility`(T128)/ `layer_type` の2の位 |
| 単位が行ごとに違う | `canvas_w` が mm の行と px の行(T126) |
| 母集団が書かれていない | ファイル 9,653 と 異なり 7,418 / 腕 1,681 と 1,392(T131) |
| 不在が範囲だった | 層 PNG の 173 / `.lip` 1,986(T119・T126) |

> **だから集計は「数の表」ではなく「数と、その数が答えない問いの表」である。**
> **これが無い集計は、重さを減らさない。**

## 1. 置き場と、公開の線(**決定済み 2026-10-26**)

- **`data/` には置かない**(`.gitignore` 済み。原稿由来の納品物の場所)
- **`census/` を新設**し、**追跡する**(集計のみ)
- **`origin` は匿名で読める = 公開リポジトリである**(2026-10-26 に確認)。
  したがって `census/` に入れたものは**全世界から読める**

**ユーザーの決定: 段 A(集計のみ・固有名なし)。**
`census/` に出すのは**年・形式・種別ごとの件数と分布**だけで、**作品名も層名も出さない。**

---

## 2. 粒度の3段(**どれを公開するかの選択肢**)

| 段 | 中身 | 公開の含意 |
|---|---|---|
| **A 集計のみ ← 採用** | 年・形式・種別ごとの**件数と分布**。固有名を一切出さない(「2018年の作品7件」) | **作者の固有情報を公開しない** |
| **B 作品名まで** | A + 作品フォルダー名(`ako6`・`tomoe_dl`・`akogareFANBOX` …) | **未公開原稿の題名・企画名が公開される** |
| **C 層の名前まで** | B + 層名の分布(`線画 hair`・`肌グラデ`・`乳首グラデ` …) | **作者の私的な作業名が公開される** |

**器具は C まで作り、`census/` に出すのは A だけ**にする(**集計は手元で全部持ち、公開は
切り落とす**)。**手元の全量は `data/` 配下**に置けば追跡されない。
→ **UI は手元では B・C まで見られる。公開されるのは A だけ。**

**器具の形(これは規律であって実装ではない)**:
- **1本の器具が、同じ集計から `census/`(A)と `data/census_full/`(C)を同時に出す。**
  **2本に分けない** —— 分けると「公開版だけ古い」が起きる(T131 の形)
- **A を作る段で固有名を落とすのではなく、`name` 列を一度も書かない関数を通す。**
  **落とす実装は、落とし忘れを静かに通す**(T104)
- **`census/` に出す全ファイルについて、固有名を含む列が0であることを器具が印字する**
  —— **印字が無い走行の出力を commit しない**

## 3. 持つもの(案)

### 3-1. 母集団

```
ファイル     .clip 7,667 / .lip 1,986 / 計 9,653
異なり       .clip 6,194 / .lip 1,224 / 計 7,418
層           312,898(.lip を入れた後の数は未集計)
```

**毎回この2つを並べる**(ファイル数と異なり数は別の量。T96 の形)。

### 3-2. 層の種別 × 中身

`v_layer_kind` の11種別 × `rendered` × `drawn_ratio > 0` × マスクの有無。
**依頼3の872頁については既に在る**(`f_request3_layer_kind_rendered_20261026.csv`、56,576行)。

### 3-3. **各列の「答えない問い」**(この集計の本体)

| 列 | 答える | **答えない** |
|---|---|---|
| `drawn_ratio` | アルファ26以上の画素の割合 | **墨があるか**(閾は128)。**`image_material` と `mask_fill` では「空」を意味しない**(T129) |
| `visibility` | ビット列。1の位=表示、2の位=マスク | **等値比較してはいけない**(T128) |
| `layer_type` | ビット列。2の位=マスク | 他のビットは**未解明**(抽出側に依頼済み) |
| `has_mask` | **何も**(全2,963層で True) | T87 |
| `canvas_w/h` | 行ごとに mm か px | **`canvas_unit` を見ること。`v_canvas_px_w/h` を使う**(T126) |
| 層 PNG | **マスク前**の形 | 紙面に出ている形(マスクは掛かっていない) |
| 納品の範囲 | `drawn_ratio > 0` の層だけ | **それ以外の層が空であること**(T119・T129) |

### 3-4. 納品の覆い

どの頁・どの層にラスタが在るか。**優先65頁: 非フォルダー 5,544 のうち PNG 在り 2,963。**

## 4. 規律(集計に当てる)

- **数の隣に母集団(述語)を書く。** 2026-10-26 に3つの食い違いがこれで解けた(T127・T131)
- **供給元から取った数は、ここで誰かが測るまで、測った者の名を帯びる**(T132)
- **再生できる器具を commit する。** 集計の CSV だけでは T110 の「歩ける」3段の2段目
- **選別は2か所で書けてはならない**(T131)
- **落としたものを理由別に数えて印字する**(規律9)

## 5. UI(**track が作る**)

**要件**:
- **集計を読むだけ。原稿のラスタを表示しない**(`data/` に触らない)
- **各数の隣に §3-3 の「答えない問い」を出す** —— これが無い UI は、重さを減らさない
- **母集団の切り替え**(ファイル / 異なり、`.clip` / `.lip` / 両方)
- **公開の段(§2)に応じて、固有名を出す / 出さない**を切り替えられる

**形(決定を受けて)**: **`census/` の静的な1枚の HTML**。A の CSV を読んで表示するので、
**サーバーも要らず、clone すればどこでも開ける。**
**手元では同じ1枚が `data/census_full/` を読めば B・C まで出せる**(読む先を切り替えるだけ)。
