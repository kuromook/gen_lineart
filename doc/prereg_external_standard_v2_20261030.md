## §1 直す点1: **判定式**(第1版 §2 の欠陥)

**AUC は向きを持つ。0.5 が「分けない」で、0 も 1 も「強く分ける」。**
第1版は生の AUC を `null + 0.15` と比べたので、**帰無値が 0.1595 になった結果、
分けない軸(`width_consistency`、0.5 から 0.0301)が C2 に入り、
強く分ける軸(`deep_black_ratio`、0.4546)が C1 に入った。**

→ **第2版の主値は `|AUC − 0.5|`。** 向きは別の列に `AUC` をそのまま印字して残す
(どちら側が大きいかは読みに要る)。

**帰無値が 0.5 から大きく外れる場合の扱いを、いま書く**:
`|AUC−0.5|` は 0〜0.5 なので、**帰無値が 0.35 を超えたら C2 の棒(null+0.15)は 0.5 を超えて到達不能になる。**
**そのときは「この構成では C2 を判定できない」と書いて止める。棒を下げない。**
(第1版の帰無値は 0.3405 で、**この線のすぐ下に居た**。)

## §2 直す点2: **外部側の作り方** —— 履歴を合わせる

**作者側**: 原稿(600dpi)→ **縮小** → 480窓。**外部側(第1版)**: 1024 生成 → **縮小なし** → 480窓。
**この履歴の差が実測に出ていた**(第1版 §4-4・§5):

| | 作者側 | 外部側(第1版) | 比 |
|---|---:|---:|---|
| `line_width_p50` | 3.8200 | 1.9100 | **2倍** |
| `deep_black_ratio` | 0.0020 | 0.0351 | **18倍** |
| `faint_of_drawn_ratio` | 0.3839 | 0.2751 | — |

**第2版の外部側**: **2048 で作る → 縮小 → 480窓。** 両側に**縮小のアンチエイリアス**が入る。

### 2048 の作り方(**人の判定で選んだ。走った後に選び直さない**)

3案を同じプロンプト・同じ seed で出し、**原寸1:1で人に見てもらった**:

| 案 | 秒/枚 | 人の判定(2026-10-30) |
|---|---:|---|
| 直接 2048 生成 | 94.9 | **「線がほつれている」→ 却下** |
| **1024 → ESRGAN(`R-ESRGAN 4x+ Anime6B`)→ 再denoise 0.40** | **55.6** | **「まともに見える」→ 採用** |
| 1024 → Latent → 再denoise 0.30/0.50 | 48.1 | 「線に色が付いてる」→ 却下 |

**Claude の読みは直接2048 を「きれい」としたが、人の判定を採る**(第1条: 向きを与えるのは人の判定)。

### **この選択の代償を、いま書く**

**ESRGAN は 1024 で描かれた線を 2048 の画布に引き伸ばす。線の細部は 1024 相当のままである。**
**だから縮小すると情報的にほぼ元へ戻る。** —— **「大きく描いてから縮小した」履歴は半分しか揃わない。**
**入るのは縮小のアンチエイリアスだけで、2048 で描かれた細部は入らない。**
**この制約は結論に必ず添える。「履歴を揃えた」とは書かない。**

### 縮小率の決め方(**走る前に基準を書く。主値は見ない**)

**基準**: 作者側の3つの量 —— `line_width_p50` **3.8200** / `faint_of_drawn_ratio` **0.3839** /
`deep_black_ratio` **0.0020** —— に、**相対誤差の最大が最も小さくなる縮小率**を選ぶ。

- **候補**: 2048 → 短辺 1024 / 1280 / 1536 / 1706 / 2048(= 縮小なし)。LANCZOS
- **12枚 × 2チェックポイントの smoke で決める。AUC は一切計算しない**
- **決めた値をこの文書に追記して commit してから本番を走らせる**
- **走った後に選び直さない**

## §3 そのほか、第1版から変えるもの / 変えないもの

### 3-1. 変えない(第1版のまま)

- **作者側のプール** = `combined_koma_20260729` の 1,489タイル(457コマ、5作品)。**引き直さない**
- **白点を両側で揃える**(ユーザーの裁定)。**ただし第1版 §5 の実測を添える** ——
  本命側の紙は中央値 254 で作者側と同じだったので、**この操作が効くのは主に NC3 側である**
- **閾値 128 / 220 固定。側ごとに変えない**
- **墨の門 `ink_ratio ≥ 0.011992`**(作者側プールの最小値)。**両側に同じく当て、落とした数を印字**
- **圧縮の経路**: 両側とも quality 95 の JPEG を通った後に白点を当てる
- **配り方** 69/46/40/302 で 1,489タイル。**窓の順も第1版のまま**
- **プロンプト束・seed・チェックポイント2本**(本命 `animagine-xl-3.1` / NC3 `illustriousXL_v01`)
- **tie は 0.5。`line_width_p50` と `width_consistency` は tie 構造を隣に印字し、C1 でも「情報が無い」と読まない**
- **帯は元のコマ単位の bootstrap。タイル数と元コマ数を両方印字**

### 3-2. **NC4(両側を前処理器に通す)を外す**

**第1版で、前処理器が作者側のタイルから線をほとんど拾えないことが分かった**
(`ink_ratio` 0.0330 → **0.0006**、`long_component_ratio` 0.8128 → 0.2030)。
**原因は縁のぼけである** —— 作者側の残存率は縁のぼけで 0.565(faint<0.15)〜0.010(faint≥0.45)と50倍動き、
外部側はどの四分位でも 0.76〜0.83 で動かない。**前処理器はラフから線画を起こす器具で、
既に線画であるタイルに当てるものではない。**

→ **第2版では NC4 を回さない。C2 の条件からも外す**(第1版は「NC4 を通る」を条件に入れていた)。
**これは条件を緩める方向なので、緩めたと書く。**
**代わりの前処理の対照は、この登録では立てない。** 立てられる案(線幅を揃える)は
**第2版の正規化そのものと混ざる**ので、別の登録が要る。**無いまま走ると書く。**
