# 新 Track 起案(案): コマ生成 — concept を与えて単語を配置して「描く」

日付: 2026-09-21 / 起案: Kimi(Track F の測定結果を受けて)
状態: **草案・未承認**。承認後、新リポジトリの initial_notice として転記する。

## 背景: Track F(線の文法)が確定させたこと

5つの測定がすべて一致し、「コマ内の単語間文法」は見つからなかった:

1. 自己回帰モデル: 7.35 (unigram) から 6.94 bits/語 しか改善しない(門 6.85 で僅差不合格)
2. bigram (7.40) が unigram より悪い = 正準順序の隣接性に情報が無い
3. set-cloze: 7.398 bits で unigram にも届かない(門 6.35)
4. ショット型12個を条件にしても 7.312(改善 0.036 bits のみ)
5. WD14タグ40個を条件にしても 7.370(改善なし)

一方で**持っているもの**:
- 単語は実在する(500語 FSQ、細部除去で 23.2% 変化、使用率 92%、D=0.166)
- 単語の**空間配置**には構造がある(全条件で位置予測は周辺分布 7.56 を 6.31-6.39 に下回る)
- 単語の内側の構造は強い(B′選択 0.662、細部不変性、門5で 19/20 語に人間が名付け可能)
- コマの**場面型**(12クラスタ)が人間に場面記述として命名できるほど意味のある単位になっている

**結論: 生成は「文法が単語列を引き受ける」形では組めない。
concept(場面)を外部入力として与え、文法(モデル)の役割は
「その concept の下で、どの単語をどこに置くか」の選択と配置に限定される。**

## 5P/5C: 絵の構成を決める10要素(操作定義・Track F 2026-09-21 に確立)

ユーザーによる洞察: **線画を単語の配置として読むとき、配置を支配しているのは
10の構成要素である。現状これらが未定義なので、配置は無軌道に見えていた。**
新 track ではこれらを**特徴量として定義し、生成・評価・語の解釈のすべてに使う。**

| 要素 | 意味 | 操作定義 | 状態 |
|---|---|---|---|
| **composition** 構成 | コマのショット型 | per-コマ特徴量(単語数・密度・scale分布・plane割合・単語ヒスト・タグ)をk-means | ✅ Phase 1 実測。12型が人間に場面記述として命名可能 |
| **placement** 配置 | 語どうしの相対位置 | 語ペアの相対位置分布(型ごと) | ⬜ Phase 2。型確定後に測る |
| **plane** 面 | コマ枠・面の処理 | コマ枠に張り付くまとまりの割合 | ✅ 特徴量として実装済み(型分離に寄与) |
| **perspective** パース | 奥行きの記法 | 長い直線の収束度(消失点の有無・強度)。counter と幾何基盤を共有 | ⬜ Phase 2 |
| **proportion** 比率 | 部品の大小関係 | まとまりのスケール分布(12ビン) | ✅ 特徴量として実装済み |
| **pose** 姿勢 | 人物の姿勢 | 部品語の配置から姿勢を読む(placement の応用) | ⬜ Phase 2 |
| **counter** 線の質 | 線の画風・リズム | 集中線ではなく**線の質**: 曲率分布・直線区間割合・線幅変動・点間隔の周期性 | ⬜ Phase 2 |
| **character** 個性 | 作品・作家の画風 | 顔部品語の再帰的出現から「キャスト」(登場人物の絵柄)を発見 | ⬜ 将来 |
| **coodinate** 統一感 | 作品内の一貫性 | **1作品・シリーズ単位**での上記統計の一致度。混合コーパス全体では測らない(バラバラの作品では見極め不可) | ⬜ Phase 2。work 列(meta.csv)で作品識別可 |
| **concept** 構想 | 何を描くか | **測定対象外**。条件付け入力として与える(WD14タグ・12型が代理) | ✅ 外部入力として位置づけ済み |

## 目的

**与えられた concept(場面型/タグ、将来的には下絵やテキスト)に対して、
単語を空間に配置し、コマの線画を生成する。**

GPT たとえの整合性: Track F は「単語の並びが文法に従う」と仮定したが、
実際の漫画は「作者が描こうとしていることが文(=絵)を決める」。
つまりこちらは**条件付き生成の track**であり、無条件の「文章生成」ではない。

## 設計の柱(草案)

1. **語彙は Track F の資産をそのまま使う**:
   `results/invariance_20260920/l4_w500/codebook2.pt`(500語・回帰復号・levels 5,5,5,4)。
   単語の細部は残差 stage が保持する2段構造。
2. **生成器の形**(測定結果が示す三分割に対応):
   - **選択**(どの単語が現れるか): concept 条件 + 既置単語からの set-cloze 型。
     測定上は予測可能性が低い(7.31)ので、ここは「尤度最大化」ではなく
     「もっともらしい単語集合のサンプリング」として扱う。
   - **配置**(どこに置くか): 条件 + 既置単語から (pos_y, pos_x, scale) を予測。
     測定上ここが最も構造がある(6.31-6.39)。生成の主力。
   - **細部**: 符号化器/復号器が引き受ける(生成側の責務は置き方だけ)。
3. **評価は事前登録制**(Track F の運用ルールを継承):
   - 描画して目視(鉄則)
   - 線の統計(長さ・密度・交点)の分布一致
   - 破片化指標(捕捉率・1本あたり交点数)で「崩れた出力」でないこと
   - 条件一致: 与えた concept のタグが生成コマに現れるか
4. **禁止事項の継承**: 480pxタイル不使用、下絵不使用(初期)、判別主軸化しない、
   基準の事後緩和禁止、数値には目視モンタージュ併記。

## 積み上がりのロードマップ: ピースは相互に強化する

**前提となる認識**: 今埋まっているピースは全体の一部に過ぎない。
- **単語の名づけは道半ば**(頻出上位20語中19語まで。残り480語は未命名)。
- **5P/5C 特徴量は composition/plane/proportion しか実装されていない**(7要素は将来)。
- **細線化(分かち書きの前段)もまだまだ改善の余地がある**。

**ここに相乗効果がある**: ピースが埋まるほど残りのピースは簡単に埋まる曲線が予想される。
- counter(線の質)の特徴量が入れば、見た目が似て線質だけ違う単語の区別と名づけがしやすくなる
- 名づけが進めば、型の解釈と placement の分析が正確になる
- 細線化が改善すれば、単語の切れ目が正確になり、語彙・配置・counter のすべての測定が正確になる

**姿勢**: はじめはしんどいが、ねばり強く1ピースずつ埋める。
急いで全体像を仕上げようとせず、測定→記録→次のピースの順で確実に積む。
