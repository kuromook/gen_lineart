作者(ユーザー)から 2026-10-24 に受けた説明と、Track L が L13/L14 で測った結果。
**この文書は手順の記録であって、進行状態は持たない。** 数値の正本は `doc/work_log.md`。

## 1. 作者の手順 (原文)

> デジタルツール上での一般的にベタの作成作業は
>
> **1** 線に囲まれた領域にたいして塗りつぶしツールを実行する。この段階で線が完全に
> 閉じていればベタ塗り面は完成する。**これが我々が探してる面そのものであり、この場合
> 塗りつぶしツールの挙動さえ分かれば作成できると考える**
>
> **2** 実際には線画はきれいにとじていないことが多く、塗りつぶしを実行すると漏れる。
> このため隙間を埋める。**線画レイヤ側で作業せず、ベタレイヤ側で隙間をうめ、塗りつぶし
> ツールに線画とベタレイヤの両方を判定させる設定にして塗りつぶす**
>
> **3** これでもアンチエイリアスやアルゴリズムのために線とベタ面の間に隙間ができる
> ことがある。この場合**ベタ面を数ピクセル(大抵は1)太らせて隙間を埋める**。
> 埋まりきらないときは手作業で目視確認しながら埋める
>
> ako6/7でのベタレイヤはこのように作られているはず。そして、**この工程での複数レイヤ
> 判定を使わず直接線画レイヤに1-3工程を実行してできるのが線画・ベタ混成のレイヤ**となる。
>
> ツールはほぼ決定論的であり、**隙間埋めだけがやや特殊**だ。

## 2. この手順から直ちに従うこと

- **「面」の定義は幾何ではなく手順である。** 面とは「塗りつぶしツールが止まった範囲」。
  開き半径や面積の床は我々が後から当てた近似で、作者の定義ではない
- **線画・ベタ混成レイヤは事故ではなく、工程2の複数レイヤ判定を使わなかった結果。**
  混成レイヤを「汚れ」として捨てると、作者の作業記録を捨てることになる
- **工程2の作業場所はベタレイヤ側。** 線画レイヤを閉じる処理(morphological closing、
  端点接続、縮小)は、どれも作者がやっていないことをやっている
- **非決定論的な工程は2だけ。** 1 と 3 はツールの挙動で決まる

## 4. 既知の罠

- **T-L1 `fill_mask` の開きは「面か線か」を答えるが「ベタか効果か」は答えない。**
  1,325面のうち 354面 (26.7%) は `effect` と `描き文字` から出ている
- **T-L2 肥えた線は面に化ける。** `rendering_lineart_*` (3Dレンダラ出力層) の
  ギザギザに太い線は、半径4の開きを通って1コマに32個の「面」を作る。
  原寸: `results/l14_cleansing/l193_render_layer_native.png`
- **T-L3 データセットの線画ラスタは作者のページと同じページではない。**
  層の墨のうちラスタに在るのは 63.0%。**面層では 54.0% が丸ごと落ちている**
  (線層は 5.1%)。詳細は `doc/work_log.md` の A6 と
  `outbox/note_l_raster_missing_layers_20261024.md`
- **T-L4 `has_mask` は 2,963層すべてで True の定数。** 分割に使えない
- **T-L5 層の名前で母集団を切ってはいけない** (L8)。`線画` という名前は面層にも
  線層にも出るし、`black` は本物のベタである。切るなら形の試験で切る

## 5. 言えること

**「面を予測する」問題は「閉じた輪郭を予測する」問題と等価であり、近似が効かない。**
ベタ輪郭の 2-5割、1領域あたり 5-8本・1本 22-30px の、線に裏打ちされていない区間を
**全部**当てる必要がある。1本外すと 256倍に漏れる。

Track J (修理は届かない) と Track K (過接続も過分割も届かない) が別経路で到達した壁と
同じ壁である。

## 6. 重ね順について作者から受けた判断 (2026-10-24、規律6)

> **下絵が前に置くことはよくあった。** 直感的にはリアル空間では逆だろうが、デジタル上では
> 前後に縛られる理由はなく、むしろ作業的には前のほうがやりやすかったからだ。
> **但し、常に前にあるとは限らない。**
>
> **下絵は遮蔽物でない、という判断で問題ない。**

**これは z順を使う測定の前提への但し書きである。**

- **「前にある」は「隠している」を意味しない。** 重ね順は制作の都合で決まることがある
- **下絵 (`/sketch set`) は遮蔽物として扱わない** —— 作者の判断。L12 の修正A2
  (「下絵は入力画像であって作者のベタではない」) と同じ向きで、別の理由から同じ結論
- **位置は一定でない**(「常に前にあるとは限らない」)ので、**層の種類で一律に決められない**

実務上の点検: 前にある層が作者のベタと**大きく重なっている**なら、それは隠していない
(下絵のように「ただ上にあるだけ」)可能性が高い。`|R ∧ OCC_front| / |R|` を層ごとに見る。
